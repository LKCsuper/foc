# Hall FOC 提速调试经验：1500 → 1800 RPM

> 2026-09-17，BM75 / STM32F405RG，COM19，24 V 可调电源，电源限流设为 3.0 A。空载、Hall 反馈、`spiq 0.8`、弱磁关闭。运行时电源输入电流未记录。本文是调试方法和经验；逐次原始数据见[原因与测试记录](./Hall_1500RPM达标原因与限制_2026-09-16.md)。偶发 `|Id|>1 A` 的分型与 VESC 式处理见[Hall 偶发 Id 毛刺](./Hall偶发Id毛刺_2026-09-19.md)。电压裕量、CCR、弱磁三者怎么选见[Hall 提速：CCR、母线电压与弱磁](./弱磁.md)。

## 这次解决了什么

最初把 1500 RPM 跟不上归因于反电势过高，准备通过负 Id 弱磁提速。但串口里的 `|Vd,Vq|` 是**软件电流环请求电压**，不是电机端测得的相电压。用三路 CCR、ARR 和母线电压重建 `PWM ideal` 后发现，旧 `svm_hqd` 的理想平均 αβ 幅值仅约为软件请求的三分之一。软件先碰到约 13.9 V 的限幅，并不能说明 24 V 母线在电机端已经充分利用。

因此没有先加负 Id，而是在 **Hall + I/F 电流模式**保留原扇区、相序和 `svm_hqd`，只把其输出的三路逻辑 CCR 同比小幅放大。倍率 1.20 使 1500 RPM 通过；1.35 使 1800 RPM 进入 ±2% 范围。目标 2000 RPM 时实测仍约 1815 RPM，尚未达标。这个结果说明当前调制幅值是一个可验证的限制因素；**不能据此认定 Id/Iq 电流反馈已准确，或 3000 RPM 不需要弱磁**。

## 有效的调试顺序

1. **先建立停机与基线。** 在 COM19 发 `olstop` 并检查 `olsnap`：输出关闭、目标为 0、无故障；确认电源限流设为 3.0 A。该数值是直流电源的限流设置，不能代替运行时输入电流，也不能直接当作定子 Id/Iq 限值。
2. **把“请求”和“输出估算”同时记下。** 每档记录目标/实测转速、`Speed Iq`、Id/Iq 目标与反馈、`Vd,Vq out`、`PWM ideal`、母线电压、故障码和采样方向计数。`PWM ideal` 只是由 CCR 推得的理想平均值，仍需示波器验证端子波形。
3. **一次只改一个可回退变量。** 保持弱磁 0 A、速度/电流环参数及底层外设配置不变，Hall CCR 倍率依次试 1.20、1.30、1.35。每次固件改动后先重新编译、烧录、校验，再从 150 RPM 起转并逐档升速。
4. **用实测值判目标，不只看脚本 PASS。** 1.30 倍时目标 1800、三次实测均为 1730.8 RPM，低了 69.2 RPM；旧 ±5% 容差却判通过。将 1800、2000 档收紧到 ±2% 后，1.35 倍的 1800 三次为 1785.7、1785.7、1814.5 RPM，2000 首次仅 1814.5 RPM 并明确判失败。每次结束确认 `olstop`。
5. **达标后看另一条控制链。** 1800 转速进入容差时，Id 目标为 0 A，快照曾出现约 +0.923 A；另一次 1500 档约 +1.176 A。Iq 也随 Hall 扇区变化。转速达标只是空载速度环结果，电流采样与控制仍需排查。

## 踩过的坑

- **把软件限幅当成母线物理极限。** `|Vd,Vq|≈Vbus/√3` 只能说明控制器请求被限幅；需要结合 CCR 和实测 PWM，才知道实际输出用了多少电压。
- **用电流指令继续“硬推”饱和速度。** 2000 档 `Speed Iq` 已到脚本设定的 0.8 A，Iq 快照却只有 0.295 A，软件电压请求贴近上限。此时盲目提高 Iq 指令不能证明能升速，还会放大电流风险。
- **验收容差掩盖平台转速。** 1800 档 ±5% 允许低到 1710 RPM；1730.8 RPM 会通过脚本，但不应写成“达到 1800”。报告应列出原始实测及容差。
- **一次改成理论满幅调制。** 曾直接换标准线性 SVPWM，150 RPM 起转仅约 58 RPM，已撤回。旧扇区、相序、采样和调制单位的关系尚未全部厘清，应小步改变并逐档回归。
- **把采样侧固定当成电流误差已修复。** Hall 控制只处理 TIM1 向下计数侧 ADC/DMA 帧，使采样时机确定；Id/Iq 偏差依旧存在。1500 首次通过也发生在该调整之前，不能混淆因果。

## 下次继续前

当前试验固件的 Hall CCR 倍率为 **1.35**，弱磁默认 **0 A**；仅证实空载 1800 RPM 在 ±2% 内，2000 RPM 未达标。先记录各速度档的电源面板**实际输入电流**，利用板上 ADC 数据检查零偏、三相电流和、相序、Hall 角度及扇区边界，再复测 Id/Iq 跟踪。如后续能借到示波器，再直接核对 PWM、ADC 采样窗口和三相电流波形。上述问题没有定位前，不把继续提高倍率或启用负 Id 当作已验证方案。

底层 ADC、PWM、定时器、DMA 和同步触发属于 VESC 来源的硬件基线。本次未改动；后续确需修改时，按项目规则先核对锁定的 VESC 实现、MCU 时钟树、BM75 IO 定义及原理图，并取得用户确认。

## 后续诊断：三相电流和与 Id 偏差

在 `olsnap` 增加同一快照中的三相电流和、CURR1/2/3 原始 ADC 计数及零偏计数；没有改变采样外设或控制参数。主机测试通过，Keil 编译 0 错误、0 警告，J-Link 烧录校验通过。新固件在 COM19 从 150 RPM 起转并逐档到 1800 RPM，三次实测均为 1785.7 RPM，结束后 `olstop` 已确认。见[150 RPM 日志](../verify/hall_verify_862ec890-dirty_20260917-203451_150RPM.log)和[1800 RPM 日志](../verify/hall_verify_862ec890-dirty_20260917-203701_1800RPM.log)。

- 停机时原始计数约 `2045/2044/2043`、零偏约 `2044.4/2043.5/2043.5`，三相电流和约 `+0.047 A`。150 RPM 运行中曾出现电流和 `−0.679 A`，对应原始计数 `2037/2038/2048`，零偏未变。这说明该次偏差不能只用固定零偏解释；可能涉及 PWM 运行时的采样窗口、噪声或电流换算，尚无波形证据确定原因。
- 1800 RPM 的一个快照显示 `Id=+1.698 A`（目标 0 A）、`Iq=+0.318 A`，但三相电流和仅 `−0.034 A`。因此即使三相和接近零，Id 仍可能大幅偏离目标；不能把全部 Id 波动归结为三相共同零偏。还需核对 Hall 电角度、相序、采样时序及电流环电压余量。
- 验证脚本新增 `|Id−Id_target|>1.0 A` 即停止的诊断门槛。该门槛检查串口快照，不替代板上实时保护；今后升速测试若触发应先分析日志，不继续提速。

把 2026-09-17 已有的 1500/1800 RPM 快照按 Hall `state` 归类，`state=1` 的 Id 在 1500 档 3 次为 `+0.910～+1.176 A`，在 1800 档 4 次为 `+0.462～+1.698 A`（目标均为 0 A）；其他扇区也有正负误差。这是**扇区相关性线索**，样本数量和快照时刻都有限，不能直接判定 Hall 标定表错误。下一轮先读取并核对六个有效 Hall 表项、边沿顺序与角度插值，再结合示波器测量核实电流采样时刻，避免凭单点 Id 值改相序或外设配置。

随后在停机可读的 `olsnap` 增加 Hall 表输出。实机表项按状态 0～7 为 `255, 132, 68, 102, 2, 166, 33, 255`；按电角度排序的有效状态为 `4→6→2→3→1→5`，相邻编码差约 30～36/200 周，即接近 60°，**未见明显缺项或顺序错乱**。这不能证明整张表的绝对角度正确。该版固件只做了 150 RPM 起转验证，3 次转速均约 150 RPM，已确认停机；其中一次三相电流和达到 `+1.175 A`，原始 ADC 计数为 `2052/2044/2050`，见[Hall 表与低速采样日志](../verify/hall_verify_862ec890-dirty_20260917-204204_150RPM.log)。异常并非高转速才出现。

脚本进一步加入 `|Ia+Ib+Ic|>0.5 A` 的快照中止条件，结合前述 `|Id−Id_target|>1.0 A` 门槛。已用上述 150 RPM 的 `+1.175 A` 样本和 1800 RPM 的 `Id=+1.698 A` 样本回放验证，分别触发相应中止。电流或母线异常即使开启 `--keep-going` 或 `all` 模式也必须停机，只有普通转速偏差可按选项继续。两项都是**串口快照的诊断门槛**，不是实时硬件保护；在确认电流采样可信前，不再据转速 PASS 继续抬高目标。

## 采样时序的代码核对（未改外设配置）

- [FOC ADC 配置](../../Library/Bsp/bsp_adc.c) 为三重规则同步转换；rank 2 是 CURR1/2/3，采样时间设为 15 ADC 周期。[DMA 配置](../../Library/Bsp/bsp_dma.c) 以 15 个半字循环搬运，当前电流通道下标为 3/4/5，因此在整组传输完成中断后进入 FOC，而非半传输中断。[采样换算](../../App/motor/motor_sense.c) 将物理 CURR1/3/2 映射到控制的 A/B/C，相序与 PWM 的 A/C/B 映射一致。
- [TIM2 触发配置](../../Library/Bsp/bsp_tim.c) 由 TIM1 更新事件复位 TIM2，再用 TIM2 CC2 触发规则组 ADC。当前 `MCPWM_FOC_CURRENT_SAMP_OFFSET=2`，对应 `TIM2->CCR2=1`；[锁定的 VESC 实现](../../ThirtyLibrary/bldc/motor/mcpwm_foc.c)使用相同的宏结构。Hall FOC 只处理 TIM1 向下计数侧 DMA 帧，代码上对应顶部更新事件之后的采样路径。
- 这些静态核对**没有证明** ADC 实际采样点、模拟放大器输出或 PWM 极性在板上符合预期；尤其无法解释运行快照中 `Ia+Ib+Ic` 偶发超过 1 A。后续应测 CURR1/2/3 模拟输出和 TIM1/TIM2 触发相位，确认波形后再决定是否需要修改任何外设基线。

用户当前没有示波器，因此不把波形测量作为继续排查的前置条件。先保持弱磁关闭和 1.35 倍率，在低速用板上已有 ADC 计数、三相电流和、Id/Iq 与 Hall 状态做多点统计，记录异常出现的频率及扇区；同时记录电源面板的**运行时输入电流**。现有 `olsnap` 只是稀疏瞬时快照，不能估计异常占比，也无法还原 ADC 触发波形。未得到更充分的电流可信度证据前，不继续升至 2000 RPM 以上。

修正脚本的 `--keep-going` 分支后，在 COM19 仅复测了 150 RPM：[低速复测日志](../verify/hall_verify_862ec890-dirty_20260917-204958_150RPM.log)。3 个快照的转速约 149～151 RPM，三相和分别为 `−0.115/+0.369/+0.208 A`，Id 分别为 `+0.003/+0.379/−0.489 A`；此次未触发诊断门槛，脚本结束已发出 `olstop`。此前同档出现过 `+1.175 A`，所以本次通过只能说明这 3 个采样点未越界，**不能证明异常消失**。主机测试还验证了 `--keep-going` 下三相和、Id 跟踪或母线异常会中止；普通转速误差仍可按选项继续。

## 停机对照与 1800 RPM 累计结果

在桥臂停机、目标 0 RPM 时，连续读取 80 次 `olsnap`，[原始 ADC 计数](../verify/hall_idle_current_20260917_80samples.csv)中 12 次三相和绝对值超过 0.5 A，最大 1.176 A；平均三相和约 +0.261 A。三路 ADC 均值比存储零点各高约 0.8～1.5 个计数。由此可知 `0.5 A` 会对停机零偏和量化噪声报警，不能直接作为运行故障的中止门槛。脚本仍记录超过 0.5 A 的提示，但超过停机观测最大值的 `1.5 A` 才中止；这只是本台架的诊断阈值，不是电流保护设定。Id 跟踪偏差 `1.0 A` 的中止门槛没有放宽。

随后将板上统计改为目标 RPM 变化时清零，并逐档复测到 1800 RPM。[原始日志](../verify/hall_verify_862ec890-dirty_20260917-211705_1800RPM.log)中的 3 个 1800 RPM 串口快照为 1785.7、1814.5、1785.7 RPM，均在 ±2% 内，**但板上累计统计显示 9652 个抽样中有 1043 个（10.8%）的 `|Id−目标|>1.0 A`**，最大 1.999 A；状态 1、2 分别占 456/1468、427/1785。这证明稀疏快照给出的“转速 PASS”不能作为电流环通过结论。脚本现已在每档结束时读取 `olcurdiag`，有任何累计 Id 越界就中止并停机；原先该次的 PASS 应按新判据视为 **未通过**，不继续升速。

该次测试停机后的第一次统计读取已完成，但之后查询发现 `ABS_OVER_CURRENT` 锁存。`olfault` 快照为目标/斜坡 0 RPM、`Ipeak=12.121 A`、母线 24.12 V，说明故障发生在下达停机之后，不能把测试结束时的 `olstop` 回显当作安全停机验收。此前 `Motor_SetCommand(enable=false)` 仅把三相 CCR 设为中点，桥臂仍输出相同占空比；旋转中可能形成短路制动电流。这是**代码推断**，没有波形或电源电流实测证明 12.121 A 的具体来源。已将停机命令改为调用现有 `Hal_Motor_PwmStop` 关断三相互补输出，未改动底层 TIM/PWM 配置；验证脚本新增停机后 `olsnap` 与故障检查。

修正后的固件 Keil 编译 0 错误、0 警告，J-Link 烧录校验通过；只做了 [150 RPM 起停验证](../verify/hall_verify_862ec890-dirty_20260917-220830_150RPM.log)：速度 148.8、149.7、150.6 RPM，累计 Id 越界 0，停机快照为 Enable OFF、目标 0、故障 CLEAR。停机约 49 秒后再次查询 `olfault` / `olsnap`，仍无故障。**尚未复测高速停机**，不能宣称 1800 RPM 的停机过流问题已经彻底解决；在确认原因和运行时电源输入电流前，不再升速。

## 逐档复测与 Hall 扇区内位置

停机修正后，逐档至 [800 RPM](../verify/hall_verify_862ec890-dirty_20260917-221438_800RPM.log) 的累计 `Id` 越界均为 0，停机后延迟查询仍无故障。[第一次 1200 RPM 复测](../verify/hall_verify_862ec890-dirty_20260917-221629_1200RPM.log)记录到 80/7495 次 `|Id−目标|>1 A`，其中状态 2 为 72/1407 次；软件请求电压约 9.2 V，低于当时约 13.9 V 的限幅。因此 1200 RPM 已需要排查扇区相关电流误差，不能仅归因于电压饱和。

为缩小范围，`olcurdiag` 增加每个 Hall 状态的前、后半扇区抽样数和 Id 越界数。前后半位置用**最近 Hall 边沿的时间、Hall 转速与极对数估算**，并非独立测得的电角度。新增统计经主机测试、Keil 编译（0 错误、0 警告）和 J-Link 烧录校验。随后仅复测到 [1200 RPM](../verify/hall_verify_862ec890-dirty_20260917-222025_1200RPM.log)：目标 1200 的三次速度快照为 1209.7、1196.8、1196.8 RPM，但 7478 个板上抽样中有 102 个 Id 越界（1.36%），最大 1.294 A。状态 2 占 86/1402 次，且这 86 次全部位于估算的后半扇区（后半 764 次、前半 638 次）；状态 1 的 13 次中，12 次位于前半。脚本据累计 Id 越界主动中止并执行 `olstop`。停机即时快照及约 37 秒后的 `olfault` / `olsnap` 均为故障 CLEAR、Enable OFF、目标 0。这些数据提示应先检查 Hall 边沿到控制角度的关系，也要检查运行时电流采样；**不能据此断定 Hall 表、相序或 ADC 触发配置有错**。

同一轮复测还出现了新的三相和变化：150 RPM 有 6337/10286 次 `|Ia+Ib+Ic|>0.5 A`，最大 1.820 A；先前同档为 682/10574 次（6.45%）、最大 1.001 A。1200 RPM 本次为 3751/7478 次、最大 1.658 A，上一轮为 619/7495 次、最大约 1.014 A。停机后零偏寄存值仍为 `2044.4/2043.5/2043.5`，但单次停机快照不足以解释运行中的分布变化。两次固件、运行条件或采样干扰的差异尚未隔离，不能把原因归给新增统计代码，也不能认为旧的 0.5 A 占比仍适用于当前板况。

验证脚本现对 `olcurdiag` 的**各扇区三相和最大值**也执行 1.5 A 中止判据；原先仅检查稀疏 `olsnap` 的三相和，可能漏掉这类峰值。该改动通过主机测试后，在 COM19 仅运行 [150 RPM 低速复测](../verify/hall_verify_862ec890-dirty_20260917-222257_150RPM.log)：累计 10301 个抽样中，各状态均出现大量 `|Ia+Ib+Ic|>0.5 A`，状态 3 最大 1.658 A；`Id` 越界数仍为 0。脚本按新增判据中止并执行 `olstop`，即时及约 8 秒后的故障检查为 CLEAR、Enable OFF、目标 0。这说明三相和问题在低速复现，也验证了累计峰值保护会阻止继续升速。下一轮应先记录电源面板运行时输入电流，比较停机和运行时的 ADC 原始计数、零偏及采样条件；在找到原因前不再升速。当前 1200 RPM 及以上不能记为电流环验收通过，1800 RPM 停机安全性也仍未验证。

停机后又采集 [80 次原始 ADC 对照](../verify/hall_idle_current_20260917_after_phase_run_80samples.csv)：6 次三相和超过 0.5 A，最大 1.095 A，平均三相和 +0.166 A；CURR1/2/3 均值约为 2045.013/2044.112/2044.350 计数。相较此前停机的 12/80 次、最大 1.176 A，这组停机数据没有同步出现运行中约半数抽样超过 0.5 A 的变化。静态代码核对确认三路电流在三分流配置下均从同一采样帧更新，`ia/ib/ic` 对应 CURR1/CURR3/CURR2；该相序置换本身不会改变三相电流和。更应优先比较**PWM 开启与关闭**时的采样读数及采样时刻，现有数据还不能区分模拟干扰、采样窗口和其他时序因素。

按本板 `3.3 V / 4095 / (0.0005 Ω × 20)` 计算，电流比例约为 **0.08059 A/ADC 计数**。150 RPM 的一次快照中，CURR1/2/3 原始值为 `2051/2045/2050`，存储零点为 `2044.4/2043.5/2043.5`；三路计数差之和是 14.6，换算为 **+1.177 A**，与日志 `Iabc sum=+1.175 A` 的显示精度一致。另两次运行快照的三相和为 +0.772、+1.094 A。故异常已存在于原始 ADC 计数相对零点的总和中，不是 `ia/ib/ic` 相序交换或 `Iabc sum` 打印公式造成。该算式也不能说明偏差发生在分流器、放大器、ADC 还是采样时序；无示波器时不能将其定性为真实定子零序电流。

## 电流滤波控制脚的静态核对

[BM75 IO 定义](../sch/BM75_IO定义.md)及 `BM75_Core.pdf` 显示：PD2 的 `CURR_FILTER` 接三颗 `MC74VHC1G66` 的控制端，模拟开关用于接入 INA240 输出滤波。当前 `bsp_gpio.c` 中 PD2 初始化已注释，`hw_hd75.h` 没有定义 `CURRENT_FILTER_ON/OFF`，因此工程中同名宏按 `hw.h` 展开为空操作；BLDC 初始化中的 `CURRENT_FILTER_ON()` 也不会驱动此脚。相电压滤波用的 PC13 另有明确初始化，不能用它推断 PD2 状态。锁定的 VESC 源码在支持该滤波脚的其他板型中会配置 GPIO 并调用 `CURRENT_FILTER_ON()`，但这不是本 BM75 板已启用滤波的证据。

**工作假设**：`BM75_Core.pdf` 的 MCU 页把 PD2 直接接到 `CURR_FILTER` 网络，Shunt Amplifier 页把该网络接到 U7/U8/U9 的 ON/OFF 脚；两页未画出该网络的上拉或下拉电阻。结合固件未主动驱动 PD2，滤波开关状态可能不确定，进而改变 PWM 运行时的电流采样噪声。仍须核实实物板的焊接、可能的板外连接及 PD2 实际电平，不能把它直接认定为此次三相和偏大的原因。下一步先测实物控制脚电平并记录运行时电源输入电流；若要做固定开/关滤波的对照试验，应单独评估 GPIO 控制对三路电流反馈及停机后 FOC 基线的影响，再限于低速执行。此处未修改任何 GPIO、ADC、PWM、定时器或 DMA 配置。

停机且 `Enable OFF`、目标 0、故障 CLEAR 时，用 J-Link **只读** STM32F405 的 GPIOD 寄存器：`MODER(0x40020C00)=0x00000000`，`PUPDR(0x40020C0C)=0x00000000`，`IDR(0x40020C10)=0x00000004`（连续读取三次相同）。PD2 对应第 2 位，因此当前确为**输入模式、无内部上拉或下拉**，数字输入在这几个瞬间为高。数字门限读值不能说明模拟电压余量或 PWM 运行中的稳定性；原理图未见外部拉电阻，也不能代替实物检查。J-Link 连接后再查串口，电机仍关闭、目标 0、故障 CLEAR。后续应优先用万用表测 PD2 对地电压，再考虑固定滤波状态的低速对照。

用户暂时没有万用表，因此在停机状态下用 J-Link 临时将 PD2 输出寄存器置高，再将 `MODER` 从 `0x00000000` 写为 `0x00000010`（仅 PD2 改为输出模式，原寄存器的其他位均为 0）；读回 `MODER=0x10`、`ODR=0x04`、`IDR=0x04`。此操作不修改固件、ADC/PWM/定时器/DMA 配置。保持 PD2 高电平，只做一次 [150 RPM 对照](../verify/hall_verify_862ec890-dirty_20260917-231439_150RPM.log)：10307 个稳态抽样中，6239 次 `|Ia+Ib+Ic|>0.5 A`（60.5%），最大仍为 1.658 A；状态 5 有 1 次 Id 偏差略超 1 A。脚本按 1.5 A 累计峰值判据中止并停机。前一次 PD2 输入模式的 150 RPM 对照为 4958/10301 次（48.1%）、最大 1.658 A。**固定高电平没有消除异常**；单次 A/B、不同测试时刻和没有模拟电压测量，均不足以把滤波开关完全排除，也不能解释占比差异。

试验后立刻用 J-Link 将 `MODER` 恢复为 `0x00000000`，读回 `PUPDR=0`；约 26 秒后的串口检查仍为 Enable OFF、目标 0、故障 CLEAR。**没有做固定低电平下的电机运行**，也没有继续升速。滤波控制脚暂按原固件输入状态保留。后续重点转回运行时 ADC 原始数据、采样窗口与电源输入电流的对照；三相和诊断超过 1.5 A 时仍应中止。

## 停机后的时序与桥臂状态核对

对照结束后读取 `olstatus`：FOC 报告控制频率 15 kHz、ADC 触发频率 30 kHz，中断耗时平均 14.1 µs、上电以来最大 62.0 µs。最大值接近 15 kHz 控制周期约 66.7 µs，值得在后续测试中持续观察；它是上电以来的最大值，无法定位到本次 150 RPM 稳态，也不能单独解释约 60% 的三相和越界。`TIM1 actual` 为 `ARR=5600`、三相 `CCR=2800`；`TIM1 gate` 虽显示 `CEN=1, MOE=1, CCER=1111`，但 `TIM1 ch` 为主通道使能、互补通道关闭，`CCMR1/2` 显示的通道 1～3 模式为强制无效，符合当前 `Bsp_Tim_StopPwm` 的停机实现。**不能仅凭 CEN/MOE=1 判断三相仍在输出 PWM**。串口同时显示目标 0、故障 CLEAR。此处只读状态，未变更 TIM1/TIM2、ADC 或 DMA 配置。

## 带符号统计：运行时共同正偏移

为区分单向偏移与双向噪声，`olcurdiag` 增加每个 Hall 状态的三相和**带符号均值**、正向和负向超过 0.5 A 的次数。仅增加每 16 个控制拍一次的诊断累积，不改变 ADC 采样、PI、PWM 或保护参数。主机测试通过，Keil 编译 0 错误、0 警告，J-Link 烧录校验成功。[150 RPM 实机日志](../verify/hall_verify_862ec890-dirty_20260917-232137_150RPM.log)中，10296 个稳态抽样的分状态均值为 **+0.625～+0.662 A**，加权均值约 **+0.652 A**；7371 次 `|Ia+Ib+Ic|>0.5 A`（71.6%）中，7308 次为正，63 次为负。六个状态都有相近正偏移，不能再把这组数据概括为“零均值的双向随机噪声”。累计峰值 1.739 A 触发脚本中止，目标/实测转速仍约 150 RPM，停机后故障 CLEAR；延迟读取仍为 Enable OFF、目标 0、故障 CLEAR。

同一固件停机后再读 [80 次 ADC 快照](../verify/hall_idle_current_20260917_after_signed_diag_80samples.csv)：三相和均值约 **+0.120 A**，9 次超过 0.5 A，最大 1.013 A。运行与停机的均值相差约 **+0.53 A**，相当于三路合计约 6.6 个 ADC 计数。这表明固定存储零点的静态误差不足以解释本轮运行中增加的共同正偏移；仍可能是 PWM 开启后的模拟前端、接地/参考、采样时序或其他测量条件变化，尚无法将其定位到某一器件。当前不对 ADC 计数或 Id/Iq 做未经验证的运行时补偿，也不继续升速。

## 三路 ADC 均值与 PD2 停机对照

`olcurdiag` 又加入 CURR1/2/3 原始 ADC 计数均值，仅在原有每 16 拍的稳态诊断中累积，不改变电流换算或控制输出。主机测试、Keil 编译（0 错误、0 警告）及烧录校验通过。首次 [150 RPM 日志](../verify/hall_verify_862ec890-dirty_20260917-233216_150RPM.log)有 10187 个稳态抽样，三路加权均值约为 `2045.542/2044.890/2044.517`，三相和均值约 +0.28 A、最大 1.175 A，Id 越界 0，脚本通过；同版固件停机 [80 次对照](../verify/hall_idle_current_20260917_after_raw_diag_80samples.csv)的原始均值为 `2044.850/2044.000/2044.150`，三相和均值 +0.127 A。三路运行均值分别比停机高约 0.69/0.89/0.37 个计数，合计解释该轮约 +0.16 A 的增量。相较前一轮 +0.65 A 的运行均值，变动较大，不能由新增打印视为“已修复”。重启后 PD2 仍为输入、无上下拉，数字输入短时读高。

用户没有万用表，因此只在停机时用 J-Link 做固定高/低的原始计数对照，并且在固定低时短暂尝试 150 RPM。固定低的首次运行快照三相和即为 **−2.854 A**，脚本按 1.5 A 门槛立即中止；[原始日志](../verify/hall_verify_862ec890-dirty_20260917-233408_150RPM.log)显示三路计数 `2032/2028/2036`，而存储零点仍为 `2044.4/2043.5/2043.5`。停机后仍读到约 `2032/2030/2034`，说明该偏差并非只在电机转动时产生。停机固定高的 [30 次读数](../verify/hall_idle_current_20260917_pd2_high_30samples.csv)均值为 `2045.333/2044.267/2044.467`、三相和 +0.202 A；固定低的 [30 次读数](../verify/hall_idle_current_20260917_pd2_low_30samples.csv)为 `2031.733/2031.167/2030.800`、三相和 **−3.040 A**，30 次全部超过 0.5 A。三路均约低 13 个 ADC 计数，是可重复的**滤波控制脚状态相关零点变化**；现有资料尚不能解释电路机理，不能把它等同于真实定子电流。

PD2 输出低改回输入时，数字输入短时仍为低；短暂输出高再恢复输入时，数字输入为高。这与原理图未画出上下拉、固件未设置内部上下拉的情况相符，支持控制脚没有确定的默认状态，但数字输入不能量化模拟电压。恢复后停机 [30 次读数](../verify/hall_idle_current_20260917_pd2_restored_30samples.csv)均值回到 `2045.067/2044.233/2044.267`，三相和 +0.173 A，故障 CLEAR。**未再用固定低状态启动电机**。

为了消除这个不确定的硬件状态，在 BM75 板级 `Bsp_Gpio_Init` 中先预置 PD2 高电平，再将其配置为推挽输出；不改 ADC、PWM、定时器、DMA、同步触发或电流零点。烧录后只读寄存器确认 `GPIOD MODER=0x10`、`OTYPER=0`、`PUPDR=0`、`ODR/IDR` 的 PD2 位为 1。[固定高电平固件的 150 RPM 日志](../verify/hall_verify_862ec890-dirty_20260917-234546_150RPM.log)记录三次速度 152.3/150.6/149.0 RPM，10296 个稳态抽样中 861 次三相和超过 0.5 A，最大 1.082 A，Id 越界 0；脚本通过并停机，故障 CLEAR。随后停机 [30 次原始对照](../verify/hall_idle_current_20260917_pd2_boot_high_30samples.csv)均值为 `2044.867/2044.200/2044.733`，三相和 +0.189 A，接近固定高时的既有读数。**本次修改确认了可控且稳定的滤波脚状态，并消除了固定低时的严重零点失配；尚未证明运行时剩余三相和偏移、1200 RPM 的 Id 越界或更高转速问题已经解决。**
