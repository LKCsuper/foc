# 观测器重复计算优化

本轮只修改 `App/motor/observer/motor_sensorless.c` 的同拍中间量复用：

- PLL 直接使用本拍已经规范化的极对数，不再重复执行 `fmaxf`。
- 积分后转子磁链复用积分前已算出的 L×I；电流、电感在该次调用中没有变化。
- α/β 磁链修正项各计算一次，积分与可选诊断共用；保留原乘法结合顺序。

没有跨拍缓存、没有状态结构/接口 ABI 变化，参数修改下拍仍直接生效；无感算法、增益、保护、15 kHz 控制频率、任务调度和底层外设配置不变。不是删除无感计算，也不宣称已经解决全部任务延迟。

补充同实例连续修改极对数、正负转速上限及低于 1 的极对数归一化测试，验证 PLL 限速即时更新。既有逐拍诊断一致性、已知角度、真实数学、扰动及时序测试用于回归。

Keil 严格编译 0 错误、0 警告，Code 188644（上一版 188660），RAM 不变；静态 DMA 调用深度 1120 字节，不能代替实测栈水位。代码尺寸缩小不是耗时改善的证明。

首次沙箱回归遇到编译器临时文件权限问题；提升后旧 Windows PowerShell 回归在末尾导出中文路径解码失败，之前的观测器与其他 C 测试通过。另用当前终端执行完整回归，结果见 `.build/host/observer_reuse_regression_pwsh.log`。

本轮只编译，未烧录、未启动电机。`F:/code/build` 中 map/axf/hex 已变为新构建，板上仍是旧固件；烧录前不能用新 map 解释旧固件 RAM 地址。实际时间收益需后续烧录后按相同 300 RPM 条件验证。

结论：这轮同拍复用属于小幅清理，尚不足以消除无感开启时的调度长尾。后续应继续定位观测器内部耗时或配置派生计算，不能通过提高速度/放宽保护掩盖问题。
