# 无感轻量记录

轻量记录用于捕获接管时的角度、电流、磁链和时序，不改变控制算法、保护阈值或 ADC/PWM 配置。

## 半周期原始ADC基线：仅停机

`slhandoff half` 只供停机时核查相邻DMA服务回调。先确认Enable OFF、目标0，再执行`slcadence stop`、`slhandoff half`；等待至少1.2秒后用`slhandoff show`冻结导出。仍复用32条缓冲，每901回调抽样，旧pair模式不变。若电机启用，ISR立即停止half诊断，不继续其读取/复制；有界运行脚本不提供half模式。

- half的ia/ib/ic字段是零占位，不是测量；离线按原始ADC、当次零偏和ACB映射换算。
- capture_flags位0/1/2/3分别表示原始值重读变化、DIR变化、NDTR变化、软件PWM提交序号变化；非零配对排除统计。零标志也不证明DMA原子一致或真实触发边沿。
- `analyze_adc_half.py`接收同一冻结缓冲的多次导出，CRC合并；停机无接管事件必须显式使用`--allow-untriggered`，并提供当次`--offsets`与`--scale`。软件PWM序号只代表COM调用，回调寄存器不能证明硬件CCR装载时刻。
- 2026-10-16停机32对数据：33～34us、方向交替、状态位0；原始通道差RMS约1.85/2.17/2.95counts，最大Clarke差折算0.246A。仅说明停机读数有差异，不是独立物理电流误差测量。
- 最初运行版在300RPM起步后串口失去及时响应，停机命令也延迟；未到600RPM，已通过调试器复位并确认停机。**该模式没有运行验收通过，现已限定停机使用。** 不允许以循环重试替代实时余量与独立停机保障。

## 推荐：32字节飞行记录

停机时执行 `sltrace compact`，随后正常启动；停机后执行 `sltrace` 或 `sltrace show` 导出CSV。
该模式专用于正常FOC的无感路径，旧的lite/flight/arm等格式继续保留。

- 每条32字节，仅时间戳、状态/事件/故障码、控制角、观测转速、Id/Iq反馈及最终目标；直接复制已计算字段。
- 复用完整记录缓冲，当前1664条，常规每30个完整控制拍采一条；15kHz时约500Hz、滚动约3.3秒。实际间隔以时间戳为准。
- 首次进入CLOSED当拍标记；退出CLOSED、故障、速度任务超过10ms未完成时立即记录事件，然后包含事件当条再留16条并冻结，正常约30ms尾段。停机当拍直接记录并冻结，不等待尾段。
- 不增加轨迹缓冲RAM；新增少量模式/事件元数据。没有额外求电压模长、编码器查询或逐拍回调计时。
- 武装时默认暂停cadence/IRQ/任务阶段统计、分段计时及旧运行耗时均值；旧读数保留，不能当当前占用。显式执行 `slcadence lean` 可在对照实验时恢复性能采样。
- 速度任务只持续发布一个完成时间戳，超时触发不依赖性能统计开启。记录器只冻结数据，不替代控制保护或主动停机。

导出格式：`seq,time_us,flags,theta,rpm,id,iq,id_cmd,iq_cmd,crc32`。单位为us、rad、机械RPM、A。
序号和CRC只在停机导出时添加，不增大32字节采样。CRC校验最后逗号之前的ASCII正文，
多项式0x04C11DB7、MSB先行、初值0，无最终异或。主机验证条数、序号、时间顺序和逐行CRC，最多重读3次冻结缓冲，
按序号合并校验通过的行；重复序号的有效正文不一致时拒绝合并。未校验通过的行不猜补，无法凑齐则报错。
测试脚本保存独立的 `*_verified.csv`，原始收发保留在日志中。

停机后也可独立重读冻结缓冲：

```text
python Scripts/compact_trace.py --port COM15 --output Doc/verify/compact_verified.csv
```

该工具先检查电机OFF，只导出数据，不启动电机；端口按当前连接选择。
`flags & 3`为状态；128失锁、256首次接管、512故障、1024任务超时、2048停机，`flags >> 16`为故障码。
缓冲只保留末段，不能当作长时间全程记录；触发尾段中事件原因保留，不代表每条都是一次新事件。

复现脚本支持 `--modes off compact --timing lean --duration 60` 做相同计时口径对照；
日常仅记录可用 `--modes compact --timing off`，无需附带性能计时。

## 入口

在电机停止时执行 `sltrace lite`，随后正常启动；停止后执行 `sltrace` 导出。

自动短测默认使用轻量记录。3508、24 V、7 极对的低速诊断可用：

```text
sltest --3508 --trace=lite 2 600
sltrace
```

`--3508` 模式仍限制母线22～26 V、测试速度500～600 RPM，异常/结束自动停机并恢复配置。它沿用当前RAM模型及零偏，不做参数检测。设备未连接时不执行上板测试。

## 记录方式

- 首次进入 CLOSED 前，每30个控制拍记录一次；进入和回退事件当拍立即记录。
- 首次进入 CLOSED 后，每8个控制拍记录一次，含触发当条共384条后冻结。
- 15 kHz且节拍正常时，后段覆盖约204 ms；实际间隔以记录的时间戳为准，不能用名义周期替代。
- 环形容量仍为512条。当前lite包含速度任务证据，样本96字节，完整样本104字节；各格式共用原存储，不会同时记录。
- 采集仅读取已算好的观测器字段和本拍控制字段，不查询编码器、求电压模长或重复计算电压限值。中断中不输出串口。

导出有 `trace format=lite` 标记及独立CSV表头：

```text
time_us,flags,theta,pll,flux,rpm,id,iq,id_cmd,iq_cmd,blend,loss,va,vb,gap_max_us,full_max_us
```

角度rad、电流A、磁链Wb、观测电压V、转速机械RPM、loss秒、时间戳及间隔µs。相位偏差可由 `pll-theta` 按最短角差计算；CLOSED后的该差不是独立转子真值。`flags` 保留状态、磁链/方向有效、接管(bit8)与回退(bit7)标记；轻量格式不包含编码器有效标志。

`gap_max_us`包含当前入口，`full_max_us`是前一采集窗口的完整回调峰值，不是当前拍尚未结束的耗时。

原 `arm`、`entry`、`entryfast` 完整记录保留；`entryfast`曾在实机中使接管初段间隔增至约100 µs，不作为默认模式。离线测试只能验证记录逻辑及字段，不证明新模式的实机开销或接管稳定性；须接回设备后与`--trace=off`做同工况对照。

## 离线分析

保存串口导出后运行：

```text
python Scripts/analyze_sensorless_trace.py 日志路径
```

同时支持完整和轻量CSV。输出记录间隔、接管覆盖时间、电流目标误差、磁链范围、PLL与控制角之差及回退事件；检测损坏帧和32位微秒计时回绕。记录间隔包含抽样分频，不能直接当成每拍控制周期；`gap_max_us`另行表示采集窗口中的控制间隔峰值。相位差与RPM仍是内部观测值，没有独立编码器参考。

## 无感控制步长修正（2026-10-14，待上板）

轻量记录中接管有效段的入口累计时间与原固定步长相差约10%。离线固定600 RPM输入实验中，实际平均间隔73.333 µs但按66.667 µs积分，会报告约660 RPM；使用实际间隔后报告约600 RPM。这是理想输入实验，不能据此解释全部失锁或证明实机转速。

正常FOC入口仅在运行中的无感I/F模式采用相邻完整控制入口时间差，统一传给传感器更新、保护和控制步进；其他反馈、模式及检测专用路径保持原周期。首拍使用名义周期，停机或退出该模式清除历史。支持32位微秒计数回绕。

允许间隔为名义周期的0.5～3倍（15 kHz下约33.3～200 µs），这是本次软件保护边界，尚未上板验证。超出边界立即锁存`CONTROL_TIMING`，清理控制状态并安全输出，不把异常间隔截断后继续积分。ADC/PWM/定时器/DMA配置未改。

入口时间戳包含中断调度延迟，不是ADC硬件采样时间戳；此修正仍需600 RPM关记录/轻量记录对照，核对接管、实际步长和完整回调耗时。当前主机回归通过，Keil编译0错误0警告；未烧录该版本。

## RTOS tick与任务阶段对照（2026-10-14）

轻量记录增加task_tick、task_phase、task_phase_age_us，共96字节，仍小于完整记录；phase1=周期等待入口，2=已唤醒，3=位置/关节调用完成，4=速度调用完成。phase1覆盖延时函数入口及等待，不能单凭它证明内核已把任务置为Blocked。tick仅由任务采样，ADC ISR不调用RTOS取tick API。slcadence记录最长完成间隔对应的tick增量；支持uint32回绕，主机回归通过，Keil 0错误0警告，ZI-data124436字节。固件已烧录校验。

600 RPM复测原文`3508_speed_tick_flight_20261014.log`，数值分析`3508_speed_tick_analysis_20261014.json`。511条有效、1条损坏；最长完成间隔16970020 µs，同一间隔tick增量47329，内核10 kHz即4.7329秒（约硬件时间27.9%）。记录中task_count6259持续不变，phase1持续时间最大16964212 µs，PI仍用470.6 RPM旧反馈、输出0.2396 A，而观测已报1560.6 RPM。后续任务恢复，PI输出−1 A，电流指令截为0；软件守卫phase3因观测1561.3>900 RPM中止，最终OFF、目标0、硬件故障NONE。

这排除了本次最长空档持续发生在位置环或速度PI内部，证明tick进度落后且外环发布严重迟滞；尚不能仅据计数确认ADC-DMA是唯一原因，或区分全部PendSV延迟与内核等待异常。静态配置ADC-DMA优先级1，内核最低优先级15，tick10 kHz；本次未修改任何优先级、tick频率或ADC/PWM/定时器配置。下一步核对完整中断负载及PendSV执行窗口，或评估将必要外环更新接入有界控制路径；不能未经验证直接提高tick优先级。

本轮中断统计callback计数达到1000000上限，后段full_max_us字段出现0，不能用这些窗口证明整个33秒运行峰值均一致。完整回调统计峰值68 µs、平均58.38 µs，仅代表其保留的统计窗口。两次烧录之间重新校准，不作为仅诊断开销变化的严格A/B比较。
