# 模块独立复用

统一原则：算法拿到状态、配置、输入和时间间隔，返回结果；硬件读写、任务调度、日志、Flash和全局电机接入留在适配层。纯算法不需要为不存在的硬件提供空HAL函数。保留现有源码和版权，不建立第二份算法副本。

## 已能独立导出的算法

在仓库根目录执行 `./Scripts/export_reusable_modules.ps1`，默认生成 `.build/reusable_modules/src` 与 `include`，以及来源清单。可指定 `-Destination`。编译时仅加入这个include目录，数学库按平台链接；不需要motor_param.h、HAL、CMSIS或RTOS。导出是复制，不修改原项目或删除目标目录里的其他文件；建议每次使用新的目标目录，防止自己留下的旧文件参与编译。

| 模块 | 导出源文件 | 输入/输出边界 |
|---|---|---|
|编码器核心|motor_encoder_core.c|计数、方向、极对数、实际dt；角度/PLL速度/有效性|
|MT6701协议|motor_mt6701_protocol.c|已读出的SSI帧或I²C字节；解码角度/磁场状态/错误|
|霍尔正常解码|motor_hall_angle.c|霍尔状态、校准表、极对数、dt；电角与速度|
|数学与FOC|motor_math.c、motor_utils.c、motor_foc.c|数值、角度、电压和PWM周期；变换与调制结果（包含sincos数学后端）|
|电流PI|motor_pid.c|目标/测量/增益/dt、调用者持有积分；电压输出|
|对齐/I-F/HFI启动|motor_alignment.c、motor_if_start.c、motor_hfi_start.c|各自配置、状态和采样；启动目标或估角结果|
|独立观测算法|motor_flux.c、motor_luenberger.c、motor_ekf.c、motor_smo.c|各自配置、状态、电压电流和dt；磁链/角度等|

复用不等于可以原样套用所有默认参数。角度方向、坐标变换符号、计数范围、PWM映射、采样增益以及保护范围必须和新系统对应。霍尔头还依赖motor_types.h，导出会自动带上；霍尔默认包装仍是单实例，多个实例应使用显式状态接口。

## 编码器：独立使用两份文件

最小依赖：`motor_encoder_core.c`、`motor_encoder_core.h`和标准C数学库。不会初始化GPIO、SPI、I²C、定时器，也不会自动驱动电机或保存Flash。

```c
#include "motor_encoder_core.h"

motor_encoder_runtime_t encoder;
const motor_encoder_config_t cfg = {
    .pll_bandwidth_rad_s = 30.0f,
    .max_rpm = 55000.0f,
    .jump_margin_counts = 2.0f,
    .sample_timeout_s = 0.002f
};

/* 初始化返回false时不要使用该状态；14位绝对编码器每圈16384计数。 */
bool ok = Motor_Encoder_InitState(&encoder, 16384U, false, &cfg);
/* ok为true后，每次有效新采样调用；dt_s是实际帧间隔。 */
Motor_Encoder_UpdateState(&encoder, raw_count, dt_s);
float mech_rad = Motor_Encoder_GetMechAngleState(&encoder, encoder.last_count);
float rpm = Motor_Encoder_GetMechRpmState(&encoder);
bool speed_valid = Motor_Encoder_IsSpeedValidState(&encoder);
```

示例的raw_count/dt_s由自己的驱动提供，示例顺序不是完整业务程序。CPR支持1..65536，原始计数为uint16_t。每个实例拥有独立PLL带宽、速度能力、突跳余量、超时、零点及测速历史。第一帧速度无效；后续结果需要看有效标志。传感器没有新帧时调用PredictState，不要不断把旧计数当新采样校正。更复杂的异步预测/校正接入使用PredictWithTimeoutState、SeedState、CorrectSampleState，并自行保证时间与新帧识别正确。

PLL校正步长应满足2×带宽×dt<1；max_rpm用于突跳验收与测速限幅，并非电机控制保护。实际采样率和相邻位移还必须使单圈回绕不产生歧义。零点标定需要受控对齐和方向验证；MarkZeroState只是记录调用者确认的参考点，不能替代物理标定。

当前STM32项目仍通过motor_encoder.c调用该核心，RuntimeInit兼容入口沿用电机型号的PLL默认值；硬件采集、新帧序号、1kHz参考超时、诊断以及全局电机极对数仍留在这个适配文件。motor_encoder_detect.c仍负责会转动电机的校准流程。

## MT6701：读总线和解释数据分开

拿到24位SSI帧后调用DecodeSsi，检查返回值；CRC错误不修改解码输出，不能继续消费旧输出。磁场错误返回对应错误，并输出该帧状态供诊断。超速状态沿用本项目策略，仅作为告警字段输出。I²C按现有设备读取顺序取得0x03/0x04，再交给DecodeI2c；传输成功与否由自己的驱动判断。

motor_mt6701.c保留HAL总线事务、计数发布、时钟、连续错误门槛和默认状态；它不是独立算法包的一部分。新平台可以复用协议解码，自己提供采集与错误失效策略。

## 仍需进一步拆开的集成模块

| 内容 | 仍在的依赖 | 后续拆分边界 |
|---|---|---|
|速度/位置/保护集成|MOTOR_PARAM_S、默认实例和项目反馈接入|缩小输入/配置结构，应用包装从快照映射|
|主sensorless接管|全局配置、启动、调制电压与反馈选择|独立观测步进和接管状态机，保持原符号及时序|
|参数检测与传感器标定|控制输出占用、HAL、RTOS、日志/保存|实验状态机核心与执行/打印/保存适配|
|Flash与Shell|存储平台、任务及命令解析|保留项目服务，算法不反向依赖它们|
|ADC/PWM外设|STM32/VESC硬件基线|由新平台实现HAL，不作为算法源码复制|

上述表格是实际剩余依赖，不代表已经全部拆完。现有独立flux等算法也不等于主sensorless接管已经独立化。第二平台实机验证尚未进行。

## 验证

编码器新增核心测试只链接核心与标准C，不提供HAL、全局motor、MT6701或RTOS替身；验证不同实例配置、回绕、突跳、超时、零点保留与非法初始化。原项目编码器回归保留，以核对适配层重建测速与采样策略。MT6701原I²C/SSI测试通过真实协议解码调用。

`Tests/host/run.ps1`同时导出算法包并从导出目录独立编译链接，运行核心测试；原固件Keil工程也同步引用新的源文件。主机可链接并非已通过另一种MCU的时序与硬件验收。
