## 1. 先建立整体印象（约 30 分钟）

### 1.1 项目分哪几层

```
App/              业务：FOC 算法、保护、起步、传感器、Shell（只调 HAL）
Library/Hal/      硬件抽象：hal_motor / hal_sensor + port/stm32f4
Library/Bsp/      板级驱动：TIM/ADC/DMA/GPIO（当前绑定 STM32F4）
ThirtyLibrary/    第三方：FreeRTOS、letter-shell、FlashDB
Doc/              文档与学习笔记
```

**当前主路径在 `App/`，不要从 `datatypes.h` 或 VESC 归档区开始读。**

### 1.2 控制链路一图流

```
上电 main()
  └─ Task_Init
       ├─ Bsp_Init()              时钟、GPIO、ADC、DMA、UART
       ├─ Motor_Encoder_Init()    AB 编码器（可选）
       ├─ MOTOR_Param_Init()      默认参数 + Flash 加载
       ├─ Detect_Init()           电流/电压偏移校准（约 5 s）
       ├─ Command_Init()          Shell 命令行
       └─ Hal_Motor_PwmStart()    恢复 PWM 硬件（仍不自动起转）

运行中（用户 Shell 下发 olspeed + olstart 后）：

PWM 时基 → ADC 采样 → DMA 中断
  └─ Motor_DmaInt()              App/motor/motor_it.c
       ├─ 采样换算                Motor_Sense_Update（经 Motor_It_ParamCal）
       ├─ 保护                    Motor_Protect_Run
       ├─ 开环 / I-F / 无感 / 速度环
       └─ 反 Park + SVPWM         motor_foc.c → Hal_Motor_PwmSetDuty
```

### 1.3 读代码前先知道的约定

- 业务 `.c` 在 cmd/main 等入口仍可用 `#include "includes.h"`（内部 = `includes_platform.h` + `includes_app.h`）。
- `App/motor/*`、`App/motor_sensor/*`、`motor_param`/`cal`/`detect` 为例外：不拉万能 `includes.h`，优先包含直接依赖；其中 detect 仍依赖 RTOS，不能视为已经跨平台。
- 模块划分见根目录 `AI_CODE.md`：FOC / 保护 / 起步 / 传感器 / 采样换算各一个文件；硬件经 `Hal_*`。
- Shell：`plot create current|speed|pos|sine` 输出 VOFA+ JustFloat。
- 公开函数带 `@description` 中文注释，参数带单位（A、V、RPM、rad、s）。
- 运行时状态集中在 **`MOTOR_PARAM_S`**（`App/motor_param/inc/motor_param.h`）。

## 2. 推荐阅读顺序

按阶段读，每阶段读完可以用 Shell 命令验证理解。

### 阶段 A：FOC 数学（无硬件）

| 顺序 | 文件 | 关注点 |
|------|------|--------|
| A1 | `Doc/doc/开环FOC学习笔记.md` | V/F、I/F、坐标变换概念 |
| A2 | `App/motor/motor_foc.c` | `clarke_transform` → `park_transform` → `inverse_park` → `svm` |
| A3 | `App/motor/motor_math.c` | 角度归一化、查表 sin/cos、矢量限幅 |
| A4 | `App/motor/motor_pid.c` | 单轴电流 PI |

**自检：** 能口头说明 Clarke/Park 各输入输出是什么物理量。

---

### 阶段 B：中断与控制调度（核心）

| 顺序 | 文件 | 关注点 |
|------|------|--------|
| B1 | `App/motor/inc/motor_it.h` | 文件头注释：30 kHz 采样 vs 15 kHz FOC（`FOC_CONTROL_LOOP_FREQ_DIVIDER`） |
| B2 | `App/motor/motor_it.c` | `Motor_DmaInt` → `Motor_OpenLoop_Run` → `Motor_Foc_OutputVoltage` |
| B3 | `App/motor_param/inc/motor_param.h` | `MOTOR_PARAM_S` 里 `ol_*`、电流环、无感相关字段 |
| B4 | `Library/Bsp/bsp_it.c` | DMA 中断如何调到 `Motor_DmaInt`（理解硬件触发即可） |

**自检：** 画出「一次 DMA 中断里做了哪几步」。

---

### 阶段 C：保护与故障

| 顺序 | 文件 | 关注点 |
|------|------|--------|
| C1 | `App/motor/motor_protect.c` | 过流 / 欠压 / 堵转 / 失速：阈值 + 持续时间 |
| C2 | `App/motor/inc/motor_protect.h` | `motor_protect_snapshot_t` 故障快照字段 |

**自检：** 为什么堵转保护需要「有效速度反馈」才启用？

---

### 阶段 D：起步与无感（进阶）

| 顺序 | 文件 | 关注点 |

| 顺序 | 文件 | 关注点 |

| E3 | `App/motor_param/motor_detect.c` | 上电偏移校准（非 R/L 检测） |

### 阶段 F：Shell 调试（边跑边学）

| 顺序 | 文件 | 常用命令 |
|------|------|----------|
| F1 | `App/cmd/cmd_openloop.c` | `olspeed`、`olstart`、`olstop`、`olstatus` |
| F2 | `App/cmd/cmd_detect.c` | `detect offset`、`detect hall` |
| F3 | `App/cmd/cmd_encoder.c` | `encoder show/reset/detect` |
| F4 | `App/cmd/command.c` | 命令表总览 |

**建议实验顺序：**

```text
1. 上电等待校准完成
2. olspeed 300
3. olstart

5. olstop
6. encoder show      （若接编码器）
7. detect hall       （霍尔标定，电机会转一圈）
```

## 7. 常见问题

**Q：为什么上电不自动转？**  
A：`Detect_Init()` 会占功率桥约 5 s；设计上需 Shell 明确 `olstart` 才起转。

**Q：`motor_state_t` 和 `MOTOR_PARAM_S` 什么关系？**  
A: `motor_state_t` 是 VESC 遗留观测器状态；当前开环/I-F 主路径以 **`MOTOR_PARAM_S`** 为准。

**Q：无感和开环能同时看吗？**  
A: 可以。无感观测器在后台跑，接管需满足磁链/转速/方向/相位条件，用 `olstatus` 看四项条件。

**Q：换芯片要改哪些？**  
A: 当前：`Library/Bsp/` + `hw_hd75.h` + `stm32f4xx_it.c`。重构后：主要改 `Library/Hal/port/<chip>/`。
