# 电压估计与采样时间语义核对

日期：2026-10-16。只读核对生产路径、锁定VESC和板级定义；未改生产代码、时钟、ADC/PWM/DMA配置或增益，未连接控制板。

## 1. 已确认的软件顺序

完整FOC控制拍编号为k，不以每次DMA回调编号代替。

```
DMA TC标志 → Motor_DmaInt → FOC分频
  → Motor_Sense_Update：读取当前DMA缓冲，换算i[k]，更新滤波母线
  → 电流重构（读取上次软件duty）
  → Motor_Control_Step / RunIfDrag
      → Motor_Sensorless_Update：使用保存的V_est[k-1]与i[k]
      → 电流控制，产生新vd/vq
  → Motor_OutputVoltageInternal
      → 反Park、SVM、逻辑ABC比较值重建电压
      → 保存V_est[k]供下次观测
      → ACB映射，写CCR预装载，发COM事件
```

因此没有发现正常单次FOC调用内“先用新PWM电压观察本次电流”的顺序错误。但上次软件电压是否等于两次采样之间的有效平均电压，不能仅凭这个顺序证明。

证据落点：

- `App/motor/motor_foc_isr.c`：`Motor_FocIsr_Run`先Sense、重构、控制，最后仲裁输出。
- `App/motor/motor_control.c`：`Motor_Control_RunIfDrag`调用观测器；随后控制核心才生成输出。
- `App/motor/observer/motor_sensorless.c`：内部重新Clarke当前ia/ib/ic，使用`applied_v_alpha/beta`积分；不从端电压va/vb/vc获取真实端电压。
- `App/motor/motor_output.c`：重建结果写入观测器后才调用`PwmSetDuty`和`PwmCommit`。

## 2. ADC触发与回调并非同一时刻

- 当前板定义为STM32F405RGT6，见`Doc/sch/BM75_IO定义.md`；当前通道索引CURR1/2/3=3/4/5，对应三ADC同步扫描的第2 rank。端电压在第1 rank，母线位于更后rank，并非所有模拟量同一采样孔径。
- `Library/Bsp/bsp_adc.c`使用TIM2_CC2下降沿触发regular扫描。`bsp_tim.c`单电机分支由TIM1更新TRGO复位TIM2，`TIMER_UPDATE_SAMP(2)`设置TIM2_CCR2=1。TIM1中心对齐，重复计数器0。
- `bsp_dma.c`和`bsp_it.c`按当前电流索引选择TC，不是HT；等待完整DMA扫描后才服务控制。ADC触发→第2 rank电流孔径→后续rank→DMA完成→中断服务存在延迟。
- `Hal_Motor_SampleCapture`依次读取循环DMA数组，没有冻结DMA、样本代号或硬件孔径时间戳。`time_us`在读取后取得，也不是转换触发时刻。
- 无感路径分频2只数软件回调，没有用硬件采样序号校验或固定DIR。正常无丢失时保持某一侧；若漏掉一次回调，不能凭计数继续保证原来的一侧。此前同DIR记录只说明那个窗口，不保证异常窗口。

没有证据证明当前已出现DMA混帧或漏回调；这里只说明接口不能检测并排除这些情况。

## 3. 必须纠正的概念：COM不是CCR锁存证明

`Library/Bsp/inc/bsp_tim.h`的占空比宏与锁定VESC一致：设置UDIS，依次写CCR1/2/3，再清UDIS。`bsp_tim.c`开启OCxPE；`Hal_Motor_PwmCommit`仅产生COM事件并递增可选软件序号。

STM32定时器中，CCR数值的预装载转移由更新事件UEV管理；COM/CCPC管理的是CCxE、CCxNE、OCxM等控制位，不能把COM视为CCR数值立刻生效的确认。仓库中若干“COM后CCR生效”的注释混淆了两种预装载；本次记录纠正，不改寄存器行为。

参考：[ST RM0090](https://www.st.com/resource/en/reference_manual/rm0090-stm32f407-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)，TIM1/TIM8的CR2.CCPC、EGR.COMG、CCMR.OCxPE及CCR寄存器说明；本地标准库`stm32f4xx_tim.c`的`TIM_CCPreloadControl`与`TIM_OC1PreloadConfig`也是两个独立入口。

由此：

- `pwm_sequence+1`只证明发出一次软件提交，不证明对应电流采样已受新占空比作用。
- 开启预装载时读CCR不能当作不可见活动比较值的独立证据。
- 应核对写入是否跨过预期UEV、UDIS窗口是否覆盖边界，以及下次采样前经历了几个锁存边界；现有日志没有全部证据。

## 4. 上次电压仍可能不等于采样区间平均值

若一次控制在采样后写CCR，并于之后的UEV锁存，那么采样`s[k-1]`到`s[k]`之间可能先由旧PWM作用、再由新PWM作用。即使没有漏拍，观测器所需的区间平均电压也可能近似：

`V_interval[k] = w * V_active_old + (1-w) * V_active_new`

w取决于实际采样位置、锁存边界及写入期限，不能直接规定为0.5，也不能从COM时刻得到。当前观测器只保存一个软件电压向量，不追踪这个权重。

先前“电压晚1拍”的仿真是整拍向量平移，没有UEV锁存事件或分段电压，不能代表上述混合区间；其结果不足以否定这一机制。若写入错过边界，w还可能逐拍变化。

## 5. dt也存在时间语义差别

无感I/F启用时，`Motor_Timing_ControlClockStep`以完整FOC入口的微秒时间差作为dt，首次使用名义值，后续接受0.5～3倍名义间隔。

令硬件采样时刻为s[k]、中断服务延迟为l[k]，则当前测得：

`dt_service = (s[k]-s[k-1]) + (l[k]-l[k-1])`

固定服务延迟会相消，但抖动不会。若采样保持等间隔，仅服务延迟变化，使用入口差积分就不再精确等于电流采样间隔。反之，硬件真的漏样或晚触发，使用固定dt也未必正确。因此本次不直接改回固定dt；需先区分采样时间与服务时间。

## 6. 电压数值及诊断的额外时序限制

- 电压用软件比较值及当时`motor->v_bus`重建，后者经`Motor_Sense_ApplyFrame`的0.1系数低通。它不是作用区间内母线真值，母线变化时存在幅值/时间误差；无需改底层外设就能进一步离线评估。
- 可选RAM死区估计用0.01系数滤波后的本次电流方向，保存给下一拍；这与此前仿真使用未滤波真实/带噪电流符号不同。fraction为0时整个补偿分支不执行，不能拿启用补偿的模型解释所有已有数据。
- `phase`与`step`记录在观测器更新内，电压和电流是该次积分使用的输入，可继续用于同拍分解。
- 输出之后的普通/light诊断直接读取`applied_v`时，得到的是新保存、供下拍使用的电压；磁链/PLL却是刚用上次电压算出的结果。不能把这种后输出快照的电压与磁链误认为同次积分输入。既有长窗口结论来自`phase`，不受这种混合解释影响。

## 7. VESC对照与后续

锁定`ThirtyLibrary/bldc/motor/mcpwm_foc.c`的观测器同样读取已保存vαβ及当前iαβ，电流控制后段再调用`update_valpha_vbeta`更新电压。其CCR写入也使用UDIS；不能因看到上拍电压就认定本项目多延迟了一拍。VESC还显式使用`pll_speed*dt*(0.5+offset)`补偿观测相位，本项目不能只搬这个系数：触发位置、分频和输出电压语义需要共同核对。

下一步应先做事件驱动的离线时序模型：分别表示采样孔径、UEV锁存、软件写入期限、两采样间分段真实电压，以及独立服务延迟；对照现有单向量电压与入口dt。不要先增加打印或修改ADC/PWM触发，也不从静态分析宣称发现实机根因。
