# FOC 半周期切换事件诊断

## 目标与边界

300 RPM 长窗口中，完整 FOC 的 PWM 写入从向上计数半周期切换到向下计数半周期，稀疏帧间隔相应增加约 33 us；尚未知道变化来自回调节拍还是软件计数分频。

本次只新增诊断，没有改变 ADC/PWM/定时器/DMA 配置、控制频率、分频规则、PI/PLL 增益或保护阈值。记录点位于 `Motor_FocIsr_Step` 的分频判断前后，属于正常 FOC 分派入口，不是 ADC 触发锁存或最外层 DMA 异常入口。

## 使用

1. 保持停机、目标 0，无位置/关节/BLDC/检测占用及锁存故障。
2. 命令 `slhandoff phaseedge` 预约，不会启动电机或清故障。
3. 按授权条件正常低速启动。运行期间不连接或写入 JTAG。
4. 完整控制拍的入口 DIR 首次改变后，额外保存 16 次回调并冻结；未触发则运行满 10 秒冻结。冻结只停止记录，不停止电机，必须由测试脚本正常停机。
5. 停机后 `slhandoff phaseoff` 关闭预约/记录、打印条数和原因，再按当前镜像/map 用 JTAG 读取 `g_motor_phase_debug`。不得复用上一版 RAM 地址。

64 槽环形缓冲记录每次正常 FOC 回调，不只记录完整控制拍。缓冲已满时，触发完成后通常包含 47 个触发前事件、触发事件和 16 个后续事件；过早触发或停机会保留较少事件。启动前等待不写帧，运行后退出自动冻结。不是高频打印，也不靠调试器实时轮询。

## 数据布局

新增只依赖标准整数/布尔类型的 `motor_diag_phase.h`，实现归入现有 `motor_diag_schedule.c`，未新增 Keil 源文件。`g_motor_phase_active` 为 0=停止、1=等待/运行、2=触发后收尾，停机读取前须确认归零。

描述符共 1564 字节：7 个 uint32 字段依次为 magic=`0x50484153`、version=1、head（下一写槽）、count（最多64）、seen（已记录的软件回调数）、trigger_sequence、reason。reason=1 相位改变，2 停机/手动停止，3 十秒未触发；0 表示未结束或尚未赋原因。

每事件 24 字节，6 个 uint32 依次为：

- sequence：本次预约期间软件记录序号，从 1 开始，不是硬件触发计数。
- time_us：分频判断前的软件时间戳。
- count、cr1：依次读取的 TIM1 CNT/CR1 信息；代码先读 CR1 后读 CNT，非原子锁存。
- divider：高16位为判断前 skip，低16位为判断后 skip。
- flags：bit0 是否执行完整 FOC，bits8～15 反馈源，bits16～31 配置 divider。

循环数据从 `(head + 64 - count) % 64` 开始顺序解释。读取必须配对当前校验过的固件/map；必要时停机暂停 CPU 两次读回比较，不能读取活动窗口并当作冻结数据。

## 判读限制

若相邻事件时间间隔增大、计数分频仍按规则推进，优先追查软件到达节拍或上游分派；若回调间隔正常而 skip/配置 divider/执行标志变化，则追查门控或软件分频。DIR 也可受入口延迟影响，不能仅凭方向变动判定漏触发。

该记录没有独立 ADC 触发计数，不区分硬件少触发、DMA 标志合并、延迟服务及上游路径占用。10 秒逐回调记录存在额外 RAM 写入、时基读取和调用开销，可能影响临界时序；不得称为零干扰或仅凭插桩结果确定原故障根因。默认关闭时只有状态判断，不改变返回的分频决策。

## 验证

- 真实实现主机提取测试通过：未启动等待、环形回绕、方向触发、精确追加16事件、冻结后不再写、停机保留、10秒超时及时间戳回绕。
- FOC 分派专项通过：默认关闭时原 full/skip 行为保持；开启时两种回调都记录，分频值、反馈源及执行标志正确传入。
- 首次构建发现与已有交接诊断的 `Motor_Timing_PhaseArm` 重名，已改用 `PhaseEdge*` 独立名称，不改旧功能。最终 Keil 0错误、0警告；静态 DMA 栈深度1024字节，主栈2048字节，仍需运行水位核对。
- 日志 `.build/keil/phase_edge_final_20261021.log`。未重跑此前因 BLDC busy 断言停止的完整主机回归。
- 本版本尚未烧录，未清故障、未启动电机；板上仍为上轮正常结束的长窗口版本。下一项是300 RPM事件窗口验证，不升速。

## 上板结果：软件分频正常，回调到达节拍存在缺口

用户随后要求继续，串口确认停机/目标0/fault0后烧录事件版。独立暂停读回与 HEX 的204300个有效字节全部一致。命令行 `slhandoff phaseedge` 预约后执行同条件300 RPM单档短测，保持原增益、保护、15kHz控制和4V限幅，运行期间未连接、读写或暂停JTAG。

十次安全查询均fault0、tk0，爬坡后观测299.3～302.4 RPM，无独立轴速测量。测试正常结束；最终停机、目标0、fault0，电压限幅4V、开环边界800 RPM、斜坡恢复10 RPM/s。

`phaseoff` 返回 count=64、seen=14323、trigger=14307、reason=1。当前map中描述符为 `0x20011330`，活动标志 `0x20000350` 为0，两次停机独立读回的1564字节完全一致。窗口含序号14260～14323，触发位于顺序索引47，后续16次回调齐全。上述地址不可用于其他固件。

64事件中，配置divider始终2、反馈源始终1，skip与full标志逐次严格符合原计数规则，没有计数复位、跳变或配置改变。完整FOC入口通常相隔66/67us，14305→14307为**100us**，之后恢复66/67us，但所在PWM半周期已变。

因此在这份窗口内，半周期切换不是“分频计数自己乱了”，而是分频之前的正常FOC回调入口节拍先发生变化。序号14305→14306的66us意味着软件观察到的到达间隔比名义33.33us多约半周期；它不能独立证明物理ADC触发确实少了一次。其余事件大量呈52/53us与14us交替，也不是均匀的33us到达，提示必须继续核对中断服务延迟及挂起/合并情况。

### 不作过度推断

本轮没有最外层DMA IRQ入口/出口时刻、退出时DMA标志或ADC溢出状态；尚不能区分IRQ被占用而延迟、标志合并、触发变化或上游分派影响。不能根据本窗口直接认定UDIS、DMA硬件故障或某一算法耗时是根因。记录发生在运行开始后约0.48秒的早期阶段，不代表已到300 RPM稳定平台的事件；后续安全查询才确认到达目标附近。此次逐回调插桩本身也有额外耗时。

主记录 `Doc/verify/sensorless_3508_20261021_214537.log`；事件 `Doc/verify/phase_edge_300_20261021.csv`、`.json`；原始 `.build/phase_edge_dump_20261021.bin` 与独立校验副本。当前计时保护未触发，不代表33us回调节拍始终均匀。

下一步只补最外层DMA IRQ的入口/出口与退出挂起状态，对齐同一事件窗口，判断66us缺口是否对应前一IRQ执行过长或标志合并。保持分频、保护、外设和增益不变，仍采用命令行预约、停机导出。

## DMA IRQ 配对快照（ABI v2，待上板）

现已补入同一事件的外层IRQ时间与退出状态。入口位于 `DMA2_Stream4_IRQHandler` 诊断开关判断后、原唤醒/分段计时及 BSP 回调之前；出口位于原处理之后。不开启预约时不读取这些新增状态，不改变 BSP 清标志、分频、采样或控制顺序。

IRQ进入时保存时间并清除本IRQ关联序号；正常FOC回调产生事件时绑定槽号和软件序号，退出时按序号核对补齐该槽。即使该事件已触发自动冻结，出口仍能补写最后一帧。若本IRQ没有进入正常FOC回调，不会拿上一条事件错误配对。所有新增硬件操作仅为读取，不清除DMA、ADC或NVIC状态。

描述符版本由1升至**2**，头部仍为7个uint32，但每事件由24扩为**48字节**，总长度由1564扩为**3100字节**。前6字段保持不变，追加6个uint32：

| 字段 | 含义 |
| --- | --- |
| irq_entry_us | 外层IRQ软件入口时间 |
| irq_exit_us | 原处理结束后、读取其余退出状态之前的时间 |
| dma_status | DMA2 HISR 原始退出状态，包含其他stream的位，分析时须按Stream4掩码区分 |
| adc_status | ADC公共CSR，保留三路ADC状态，不仅看ADC1 |
| dma_remaining | DMA2 Stream4 NDTR读数 |
| irq_pending | NVIC中DMA2 Stream4的pending读数 |

flags新增bit1表示该事件已补齐匹配的IRQ出口。未设置时不能把零值时间或状态当作真实测量。主机端必须检查version和总长度；旧 `.build/analyze_phase_edge_20261021.py` 仅解析v1，不适用于v2，旧地址和1564字节长度不可沿用。新的固件仍使用相同 `phaseedge`/`phaseoff` 命令，无运行中JTAG操作。

软件IRQ时间差不含异常入栈/出栈，出口时间也不含其后的状态读取、补写和函数返回开销，不能当作完整CPU异常占用。HISR、CSR、NDTR和NVIC也为顺序读取而非同一时刻硬件锁存；NVIC pending为0不代表退出前从未挂起，TC标志为1也不能独自证明已合并两个硬件事件。需结合前后时间、方向和分频序号解释。

专项测试通过：环形事件配对、冻结最后一帧仍补出口、无FOC回调时不污染前帧、结束后重复补写无效；真实外层IRQ函数提取测试覆盖默认关闭、正常开启、BSP过程中自动冻结以及与既有唤醒/分段计时共存。最终Keil 0错误0警告，静态DMA栈深1032字节、主栈2048字节，仍需运行水位验证。构建日志 `.build/keil/phase_irq_20261021.log`。未重跑整套主机回归，本轮未烧录或启动电机，板上仍为已验证的ABI v1事件版。
