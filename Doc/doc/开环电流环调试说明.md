# 开环电流环调试说明

本文记录当前工程的 I/F“角度开环 + 电流闭环”启动流程，以及在此基础上增加的无感观测器和速度环。基础调试仍应先完成 I/F，再按第 16 章授权无感接管。

- [motor_param.c](../App/motor_param/motor_param.c) — 默认电机参数和开环参数初始化、Flash 持久化。
- [motor_it.c](../App/motor/motor_it.c) — ADC-DMA 中断里执行开环 FOC、电流环 PI、SVPWM 输出。
- [cmd_openloop.c](../App/cmd/cmd_openloop.c) — 串口 shell 命令，运行时修改开环参数。
- [motor_detect.c](../App/motor_param/motor_detect.c) — VESC 风格 R/L/磁链自动检测状态机。

---

## 1. 当前控制模式

当前默认使用：

```c
gpstMotorDefault->ol_mode = MOTOR_OL_MODE_IF;
```

含义：

```text
角度开环 + 电流闭环
```

在默认未授权接管时，角度由软件按目标转速积分产生，电流由 D/Q 电流 PI 闭环控制。启用并授权无感观测器后，系统会先用这套 I/F 流程起转，再切换到观测角度和 PLL 速度闭环。

本板定义为 `HW_HAS_3_SHUNTS`，因此 Clarke 变换按 VESC 的完整三相公式计算：`Ialpha = 2/3·Ia - 1/3·Ib - 1/3·Ic`，`Ibeta = (Ib-Ic)/√3`。这样 Ic 也会参与电流反馈，不会把它忽略。

### 控制链路

```text
目标机械转速 RPM
  → 软启动斜坡 → ol_current_rpm
  → 软件积分得到电角度 theta (角度开环)
  → 采样三相电流 ia/ib/ic (ADC → 零点校正 → 电流系数)
  → Clarke/Park 得到 Id/Iq (电流反馈，实时)
  → Id/Iq PI 电流环输出 Vd/Vq (电流闭环)
  → 矢量限幅 (防积分饱和 windup)
  → 反 Park 得到 V_alpha/V_beta
  → SVPWM
  → TIM1 三相 PWM → 逆变器 → 电机
```

### 与完整 FOC 的区别

| 环节     | 本方案 (ol_mode=1)                         | 完整 FOC                   |
| -------- | ------------------------------------------ | -------------------------- |
| 角度来源 | 启动时软件积分；锁定后可切换无感观测器     | 编码器/霍尔/观测器 (闭环)  |
| 速度环   | 可选（无感 PLL 速度 PI 输出 Iq，默认关闭） | 有（速度 PI 输出 Iq 目标） |
| 电流环   | 有 (Id/Iq PI)                              | 有                         |
| 弱磁控制 | 无                                         | 有                         |

I/F 启动阶段的关键是：**角度是软件强制的，但电流是真的被闭环控制的**。强制角度失步会导致 Park 变换错误；无感接管阶段如果观测角度错误，同样会引起抖动、异响、发热或过流，因此默认用 `sltakeover 0` 阻止自动接管。

## 2. 硬件前提条件

在开始调电流环之前，必须确认以下基础链路正确。

### 2.1 PWM 输出正常

- TIM1 三相互补 PWM 有输出。
- 死区时间配置正确（上下桥臂不会直通）。
- `olstop` 后三相占空比回到 50%（安全中点电平）。

### 2.2 ADC 采样正常

- ADC-DMA 中断能正常触发 (`Motor_DmaInt`)。
- 三相电流 ADC 值在静止时接近中点 (12 位 ADC 中点 ≈ 2048，当前默认兜底值为 2045)。
- 母线电压 `v_bus` 读数正常 (如 24V 系统应接近实际电源电压)。

### 2.3 电流零点校准

电流 ADC 的零点偏移量存储在 Flash (`currentOffset[0..2]`)，代码会校验合法性：

```c
// 合法范围 (1.0V~3.0V 对应的 ADC 值)
#define MOTOR_CURRENT_OFFSET_MIN  (1000.0f)
#define MOTOR_CURRENT_OFFSET_MAX  (3000.0f)
#define MOTOR_CURRENT_OFFSET_DEFAULT (2045.0f) // 超出范围时兜底
```

调试前用 `olstatus`（或 `olspeed`）查看三相电流 `Ia/Ib/Ic`：

- 电机静止、PWM 未输出时，三相电流应接近 0。
- 如果静止时显示明显非零电流，零点偏移有问题，电流环在此基础上闭环必然出错。

### 2.4 相序确认

三相电流 ADC 通道与电机相线的映射必须正确。当前代码中 `Motor_It_ParamCal()` 里 vb/vc 的 ADC 通道与相序不是简单一一对应（见函数内注释）。如果改过硬件或换过电机，优先确认真实相序。

快速验证方法：切到 `olmode 0` (V/F 模式)，给低压低速 (`olspeed 100`, `olvlimit 8`)，看电机能否平稳转起来。能转 → 相序大概率正确；只抖不转 → 相序或电角度方向可能反了。

## 4. 主流程

### 4.1 中断驱动链

每次 ADC DMA 传输完成触发 `Motor_DmaInt()`，内部有分频机制：

```c
static bool Motor_DmaInt_ShouldRun(void)
{
    static int skip = 0;
    if (++skip >= FOC_CONTROL_LOOP_FREQ_DIVIDER) {
        skip = 0;
        return true;
    }
    return false;
}
```

当前 TIM1 使用中心对齐 PWM：完整 PWM 周期是 `15kHz`，但计数顶部和底部各触发一次 ADC，所以 ADC-DMA 回调频率是 `30kHz`。通过 `FOC_CONTROL_LOOP_FREQ_DIVIDER` 做分频，实际 FOC 运算频率 = ADC-DMA 回调频率 / 分频系数。当前设为 `2`，因此每个完整 PWM 周期运行一次 FOC，即 `15kHz`。

`ol_foc_freq` 保存 ADC-DMA 基准频率 `30kHz`，代码内部把分频系数计入控制周期 `dt`：

```c
dt = FOC_CONTROL_LOOP_FREQ_DIVIDER / ol_foc_freq
```

### 4.2 主流程

```text
Motor_DmaInt                          // DMA 中断入口 (30kHz)
  → 若 Motor_Detect_IsActive         // 参数检测互斥：跳过或执行检测步骤
  → Motor_It_ParamCal                 // 采样：三相电流/电压/母线电压 (每次)
  → Motor_Protect_Run                 // 过流/欠压/堵转/失速保护 (每次)
  → Motor_DmaInt_ShouldRun            // 分频判断 (15kHz FOC)
  → Motor_OpenLoop_Run                // 开环状态机
    → v_bus < 1V → 复位 + 安全输出
    → !ol_enable → 停机 (olstop)
    → IsReady → UpdateMotion → 预对齐/斜坡/电流闭环
  → Motor_Sensorless_Update           // 无感磁链观测器 + PLL
  → Motor_SpeedLoop_Run               // 速度 PI (若 spenable=1 且观测已锁定)
  → 再次检查故障锁存 → 必要时覆盖安全占空比
```

### 4.3 电流闭环流程 (`Motor_OpenLoop_RunCurrent`)

```text
theta = Motor_CurrentLoop_GetTheta()       // 获取角度 (启动第一拍 + 相位补偿)
Motor_CurrentFeedback_UpdateDq(theta)      // Clarke + Park → Id/Iq
Motor_CurrentTarget_Get(&id_target, &iq_target)  // 获取 Id/Iq 目标 (含低速缩放)
voltage = Motor_CurrentLoop_RunPi(...)     // PI 控制 → Vd/Vq
Motor_Foc_OutputVoltage(vd, vq, theta)     // 反 Park + SVPWM → 更新 TIM1 占空比
```

## 5. 角度开环详解

角度更新在 `Motor_OpenLoop_UpdateMotion()` → `Motor_OpenLoop_UpdateTheta()`：

```c
// 角度不能完全停在 0，否则磁场固定不动，只吸不转
if (rpm_for_angle < ol_min_rpm) {
    rpm_for_angle = ol_min_rpm;
}
// 机械转速 → 机械角速度 → 电角速度 → 积分
ol_theta += RPM2RADPS_f(rpm_for_angle) * ol_pole_pairs * dt;
utils_norm_angle_rad(&ol_theta);  // 归一化到 [0, 2π)
```

关键点：

- `olspeed` 改的是**目标速度**，软启动斜坡 (`olramp`) 决定实际转速 `ol_current_rpm` 逼近目标的速度。
- 启用预对齐时，对齐完成后角度严格跟随 `olramp` 从 0RPM 平滑加速，不再跳到 `ol_min_rpm`。这是为了防止转子从静止时跟不上突然旋转的磁场，表现为“只摆动、手推后才偶尔转”。
- 关闭预对齐的兼容旧流程中，若 `ol_current_rpm < ol_min_rpm`，角度仍按 `ol_min_rpm` 递增，以防磁场冻住。
- `ol_pole_pairs` 错了 → 电角度速度错 → 电流环控的是错误角度下的虚假 D/Q 电流 → 电机表现异常。

### 相位补偿机制

启动第一拍时，`Motor_CurrentLoop_GetTheta()` 会在积分角度上叠加一次 `ol_start_phase_boost`（默认 π/2，即 90° 电角度）：

```c
if (s_ol_was_stopped && m->ol_current_rpm > 0.0f) {
    theta += m->ol_start_phase_boost;  // 仅第一拍
    s_ol_was_stopped = false;
}
```

目的是让磁场一开始就"摆出"转矩方向，而不是从 0 角度慢慢找。后续完全跟随软件积分角度，不再叠加。

## 6. 电流闭环详解

### 6.1 电流反馈

```c
// Clarke: 三相静止 → 两相静止
clarke_transform(ia, ib, ic, &Ialpha, &Ibeta);
// Park: 两相静止 + 电角度 → 两相旋转 (D/Q)
park_transform(Ialpha, Ibeta, theta, &Id, &Iq);
```

这里依赖三件事全部正确：

1. 电流 ADC 零点正确。
2. 三相电流 ADC 通道与电机相线映射正确。
3. 软件开环角度方向和实际相序一致。

任何一个错误 → 电流环"以为自己在控电流"，实际电机会抖、响、发热甚至不转。

### 6.2 电流目标与低速缩放

```c
id_target = ol_id_set;   // 通常为 0
iq_target = ol_iq_set;   // 主要转矩电流
```

**低速 Iq 缩放**：如果未开启预对齐，当实际转速低于 `ol_min_rpm` 时，代码按比例缩小 Iq 目标：

```c
if (ol_current_rpm < ol_min_rpm && ol_min_rpm > 0.0f) {
    float scale = ol_current_rpm / ol_min_rpm;
    if (scale < 0.1f) scale = 0.1f;  // 下限 10%，不完全关断
    iq_target *= scale;
}
```

对齐已完成时则不缩放：转子已经被固定 D 轴磁场拉到已知角度，起步第一拍必须给全部 `ol_iq_set` 才能克服静摩擦。若把 `0.30A` 自动缩成 `0.03A`，转子来不及跟上为它准备的旋转磁场，就会表现为“预对齐能锁住，但不转”。

### 6.3 PI 控制器

D/Q 轴各自独立跑标准 PI：

```c
// PI 标准型 (非并联型)
vd_int += ol_current_ki * id_err * dt;  // 积分累加
vd_int = clamp(vd_int, ±v_limit);       // 积分限幅
vd = ol_current_kp * id_err + vd_int;   // P + I
```

PI 输出经过**矢量限幅**：

```c
// 不单独限 Vd/Vq，而是按矢量幅值整体限制
if (utils_saturate_vector_2d(&vd, &vq, v_limit)) {
    // 限幅发生后，回写积分项防止 windup
    ol_vd_int = vd - kp * id_err;  // 反推：积分 = 输出 - 比例
    ol_vq_int = vq - kp * iq_err;
}
```

限幅值取 `ol_vq_limit` 和 `v_bus * 0.75` 的较小值。SVPWM 保守限制到 75% 调制深度，防止过调制后 PI 持续积分（积分饱和 / windup）。

### 6.4 PI 参数调试原则

| 参数 | 增大效果                       | 减小的效果             |
| ---- | ------------------------------ | ---------------------- |
| Kp   | 响应更快、转矩更硬、电流跟随紧 | 响应软、跟随慢、更安静 |
| Ki   | 稳态误差消除快、跟踪紧         | 稳态误差消除慢、更平滑 |

**典型整定流程**：

1. 先设 Ki = 0，只调 Kp。从 0.05 开始，每次翻倍，直到电流阶跃响应出现轻微振荡。
2. 把 Kp 降到振荡值的 50%~70%。
3. 逐步加 Ki，从 Kp × 100 开始（注意：单位是 Hz 级别）。观察 `olspeed` 里的 Id/Iq 反馈是否紧跟目标。
4. Ki 过大 → 听到周期性"嗡嗡"声或电流波形过冲振荡 → Ki 减半。
5. Kp 过大 → 高频尖锐啸叫、电机发烫 → Kp 减半。

## 7. 推荐启动命令序列

### 第一步：确认基础状态

```text
olspeed
```

确认 `v_bus` 正常，电流接近 0。如果没有输出，检查串口和 DMA 中断。

### 第二步：V/F 模式验证相序

```text
olstop
olmode 0
olboost 1.0
olkvf 0.057
olvlimit 8
olramp 50
olspeed 100
olstart
```

电机能平稳转起来 → 相序、PWM、电角度方向基本正确 → 可以切电流模式。

### 第三步：电流模式低速试转

默认已启用预对齐 (`ol_align_enable=true`)，上电保持停机 (`ol_enable=false`)：

```text
olstop
olfault clear
olmode 1
olid 0
oliq 0.3
olkp 0.20
olki 30
olvlimit 8
olramp 30
olmin 30
olmax 1000
olspeed 80
```

观察：

- `olstatus` 查看 Id/Iq 反馈是否跟踪目标。
- 电机是否先短暂吸住对齐（约 0.3s），然后平稳低速旋转。
- 声音是否平顺。

### 第四步：逐步提电流

```text
# 0.3A 稳定后:
oliq 0.5
olspeed 120

# 稳定后:
oliq 0.8
olspeed 200

# 稳定后:
oliq 1.2
olspeed 300
olramp 80
```

### 第五步：调 PI

```text
# 如果电流跟随慢:
olkp 0.3
olki 50

# 如果电流抖动/尖啸:
olkp 0.10
olki 15
```

## 8. 现象诊断与调整

### 8.1 电机不转，只吸住或嗡嗡响

**优先排查**：

1. 相序不对 → V/F 模式验证。
2. 电角度方向反了 → 改 `ol_pole_pairs` 符号或检查逆 Park 角度方向。
3. `ol_pole_pairs` 不对 → 确认电机规格。
4. Iq 太小，克服不了负载转矩。
5. 电流采样方向反了或 ADC 通道映射错。

**试调参数**：

```text
oliq 0.5
olkp 0.15
olki 20
olramp 30
olspeed 80
```

如果仍然只抖不转，**先不要继续加电流**——先检查相序、电流映射、电流方向、预对齐是否生效。

### 8.2 能转但声音尖、抖、发热快

通常是电流环太硬或反馈不干净：

```text
olkp 0.08
olki 10
oliq 0.6
olvlimit 8
```

降 PI 后明显变安静 → 说明原 PI 偏大。降完后仍吵 → 可能是：

- 电流采样噪声大（需要硬件滤波或软件低通）。
- 角度增量不均匀（`ol_foc_freq` 与真实中断频率不匹配）。

### 8.3 能转但没力

逐步加转矩电流和电压限幅：

```text
oliq 0.8
oliq 1.2
olvlimit 15
```

如果加 `Iq` 后电流显示有变化但电机仍没力 → 可能是角度/相序/电流采样方向问题，而不是参数小。可以在 `olspeed` 中观察实际 Id/Iq：

- 设 `olid 0, oliq 1.5`，如果实际 Id 很大而 Iq 很小 → 角度偏移严重。
- 如果 Id/Iq 都接近目标但电机仍没力 → 角度方向反了，或实际电流与显示不符。

### 8.4 加速时丢步或突然抖

```text
olramp 30       # 降低斜坡
olspeed 80      # 降低目标速度
oliq 1.2        # 必要时增加一点转矩电流
```

失步的本质是磁场转太快，转子机械惯性跟不上。开环没有位置反馈，无法感知失步。

### 8.5 低速抖动

低速时 V/F 模式的通病——反电动势小，电压裕量少，加上没有位置反馈，容易抖。缓解方法：

- 提高 `ol_min_rpm`（如从 30 提到 60），让角度积分保持一定速度。
- 适当提高 `ol_v_boost`（V/F 模式）或 `oliq`（电流模式）。
- 降 Kp，让电流环更软。

### 8.6 静止时电流不为零

用 `olspeed` 看在 PWM 未输出时 Ia/Ib/Ic：

- 如果静止显示明显非零 → 电流零点偏移有问题。
- Flash 里存的 `currentOffset` 可能异常，代码会自动兜底到 2045，但 2045 不一定是你板子的实际中点。

### 8.7 无法启动，`olstart` 后立即保护

可能原因：

- `ol_vq_limit` 太大 → 启动瞬间电压冲击 → 过流 → 硬件保护。
- `ol_current_kp` 太大 → 启动瞬间 PI 输出跳变 → 过流。
- `ol_start_phase_boost` 不适合当前电机。

## 10. V/F 模式备用

如果电流采样还没确认，可以切到纯 V/F 模式先验证硬件链路：

```text
olstop
olmode 0
olboost 1.0
olkvf 0.057
olvlimit 8
olramp 50
olspeed 100
olstart
```

V/F 模式不闭环电流，只按频率给电压：

```text
f_elec = ol_current_rpm / 60 × ol_pole_pairs   [Hz]
Vq = ol_v_boost + ol_kv_f × f_elec              [V]  (受限幅)
Vd = 0
```

适合：

- 先确认 PWM、相序、电角度方向能不能拖动电机。
- 隔离问题——如果 V/F 能转但电流模式不能转，问题一定在电流采样或电流环参数上。
- 不需要电流采样的应用场景。

## 12. 调试顺序建议

推荐按这个顺序走：

```
1. 确认 PWM 输出正常，TIM1 三相有波形
2. 确认串口命令能输入，olspeed 能打印状态
3. 确认 v_bus 显示正常
4. 确认静止时 Ia/Ib/Ic 接近 0
5. olmode 0 低压低速确认电机能被拖起来（验证相序/电角度方向）
6. olmode 1，oliq 0.3，低速试转
7. olspeed 观察 Id/Iq 反馈是否跟踪目标
8. 慢慢提高 Iq 和 speed
9. 最后再调 Kp/Ki，让电流跟随更稳
```

**调试黄金法则**：

- 一次只改一个参数，观察声音、温升、电流和转动状态。
- 每次改参数前先用 `olspeed` 记录当前状态，方便回溯。
- 不要同时改 Kp、Ki 和 Iq——改一个，观察，再改下一个。
- 调试时不要长时间低转速大 Iq 运行，热量会迅速积累。

## 13. Flash 持久化注意事项

参数通过 Flash (`easyflash`) 持久化。重要陷阱：

1. **结构体大小变化**：`MOTOR_PARAM_S` 加了新字段后，Flash 已有大小与代码中结构体大小不一致 → 自动写默认值覆盖 Flash。
2. **开发阶段覆盖块**：`motor_param.c` 末尾有个 `// TODO：调试使用` 覆盖块，强制把代码默认值写入运行时变量。**这意味着开发阶段改 `motor_param.c` 的默认值即可生效，不需要 `ef_set_env_blob`**。
3. **生产阶段**：去掉覆盖块，用 shell 命令调参 → `ef_set_env_blob` 写 Flash → 下次上电自动加载。
4. **检测结果持久化**：`detect apply` 使用独立的 Flash key `motor_detect_result` 存储 R/L/磁链/极对数。上电时 `Motor_Detect_LoadStoredParameters()` 在覆盖块之后调用，因此 Flash 中已保存的有效检测值不受代码默认值影响。

当前覆盖块覆盖了全部运行时参数（开环、电流环、预对齐、速度环、无感参数），开发阶段改 `motor_param.c` 默认值即可生效。生产阶段需移除覆盖块，使用 shell 命令调参并通过 Flash 持久化。

## 15. 电机保护与故障锁存

保护实现位于：

- `App/Motor/motor_protect.c`：保护条件、时间去抖和故障锁存。
- `App/Motor/inc/motor_protect.h`：保护配置及对外接口。
- `App/Motor/motor_it.c`：ADC 采样完成后、FOC 输出前调用统一保护入口。

### 15.1 调用时序

```text
ADC-DMA 中断
  → 三相电流和母线电压换算
  → Motor_Protect_Run(motor, dt)
      → 独立判断过流
      → 独立判断欠压
      → 独立判断堵转
      → 独立判断失速
      → 锁存第一次故障
  → 有故障：清速度斜坡和 PI 积分，输出三相安全中点电平
  → 无故障：继续执行 FOC 和 SVPWM
```

四种保护使用各自的判断函数和计时器。某个条件中途恢复正常，只清除该保护自己的计时器。统一入口按“过流、欠压、堵转、失速”的顺序检查，同一周期出现多个异常时只锁存优先级最高的首发故障，避免连锁故障覆盖根因。

### 15.2 默认阈值

| 保护 | 默认条件                                                             | 持续时间  | 故障码                          |
| ---- | -------------------------------------------------------------------- | --------- | ------------------------------- |
| 过流 | 任一相电流绝对值`>= 10A`                                           | `0.1ms` | `FAULT_CODE_ABS_OVER_CURRENT` |
| 欠压 | 已使能且目标转速非零，母线电压`< 8V`                               | `100ms` | `FAULT_CODE_UNDER_VOLTAGE`    |
| 堵转 | 目标转速`>= 100RPM`、真实转速 `<= 30RPM`、相电流峰值 `>= 0.8A` | `1s`    | `FAULT_CODE_MOTOR_STALL`      |
| 失速 | 曾达到目标转速的 50%，随后真实转速跌到目标转速的 20% 以下            | `300ms` | `FAULT_CODE_MOTOR_SPEED_LOSS` |

这些值是当前低压、小电流调试默认值，不是所有电机通用的最终参数。正式上板前必须根据电机额定电流、电源最低工作电压、负载惯量和测速噪声重新确认。

### 15.3 堵转与失速的转速反馈

堵转和失速不能使用 `ol_target_rpm` 或 `ol_current_rpm` 作为真实转速。开环积分转速只是控制指令，即使转子完全不动也会继续变化。

当前无感实现由 `motor_sensorless.c` 在观测闭环建立后调用：

```c
Motor_SpeedFeedback_Set(observer_rpm, true);
```

处于 `OPEN_LOOP/LOCKING` 或观测失锁时调用：

```c
Motor_SpeedFeedback_Set(0.0f, false);
```

`Motor_SpeedFeedback_Set()` 会继续把速度转交给保护模块。`valid=false` 会禁用堵转和失速判断；过流和欠压保护仍然工作。

### 15.4 故障锁存与恢复

保护条件恢复正常后不会自动重新启动。故障锁存期间，`Motor_Protect_Run()` 始终返回故障状态，FOC 输出被阻止。

| Shell 命令        | 功能                                           |
| ----------------- | ---------------------------------------------- |
| `olfault`       | 查询当前故障码和锁存状态                       |
| `olfault clear` | 停止电机、清空速度及 PI 状态，然后解除故障锁存 |

执行 `olfault clear` 后电机保持停止。必须先排除故障原因，再执行 `olstart` 或设置新的 `olspeed`。不要在未检查电源、功率管、电机堵塞和电流采样的情况下连续清除故障重启。

## 16. 无感观测器与速度环

### 16.1 控制层级

无位置传感器时，电机在静止状态没有足够反电动势，磁链观测器无法直接判断转子角度。因此必须分两个阶段：

```text
阶段一：I/F 开环启动
  软件积分电角度 + 手动 ol_iq_set
  → 电机先转起来，同时 Ortega 观测器在后台估算磁链

阶段二：无感闭环
  观测器角度稳定且转速达到门槛
  → 开环角度渐变到 PLL 观测角度
  → PLL 机械转速进入速度 PI
  → 速度 PI 输出 Iq 目标
  → 电流 PI 输出 Vd/Vq
```

这解决了无感控制的“零速不可观”问题：`spenable 1` 后并不会在零速直接运行速度 PI，而是先继续使用 `oliq` 起转，观测器进入 `CLOSED` 后速度 PI 才接管 Iq。

### 16.2 代码位置

- `App/Motor/motor_sensorless.c`：Ortega 磁链观测器、PLL、锁定、角度渐变和失锁回退。
- `App/Motor/inc/motor_sensorless.h`：无感状态和查询接口。
- `App/Motor/motor_speed.c`：与反馈源无关的速度 PI 和抗积分饱和。
- `App/Motor/motor_it.c`：I/F 启动、观测器更新、速度外环和电流内环的执行顺序。
- `App/Motor_Param/inc/motor_param.h`：速度环与无感参数。

### 16.3 Ortega 磁链观测器

观测器输入为上一控制周期下发的 `Vα/Vβ` 和本周期采样得到的 `Iα/Iβ`。参数全部使用 SI 单位：电阻用 Ω、电感用 H、磁链用 Wb。

```text
转子磁链 α = xα - L × Iα
转子磁链 β = xβ - L × Iβ
观测角度 = atan2(转子磁链 β, 转子磁链 α)
```

默认电机参数：

| 参数                         | 默认值       | 原始工程标称值  |
| ---------------------------- | ------------ | --------------- |
| `sensorless_motor_r`       | `0.4Ω`    | `400mΩ`      |
| `sensorless_motor_l`       | `0.0008H`  | `800uH`       |
| `sensorless_flux_linkage`  | `0.0091Wb` | `9.1mWb`      |
| `sensorless_observer_gain` | `12000000` | Ortega 收敛增益 |
| `sensorless_pll_kp`        | `2000`     | PLL 比例增益    |
| `sensorless_pll_ki`        | `30000`    | PLL 积分增益    |

电阻、电感或磁链填错数量级时，观测角度不会可靠。尤其不能把 `400mΩ` 直接写成 `400Ω`，也不能把 `800uH` 直接写成 `800H`。

### 16.4 状态切换

`speed` 命令显示以下状态：

| 状态          | 含义                                                 |
| ------------- | ---------------------------------------------------- |
| `OPEN_LOOP` | 使用 I/F 强制角度，观测器尚未满足接管条件            |
| `LOCKING`   | 磁链、方向、速度和相位误差暂时合格，正在累计锁定时间 |
| `CLOSED`    | 观测角度已经接管，PLL 转速可用于速度 PI              |

默认接管条件：

- 机械转速绝对值达到 `500RPM`。
- 估算磁链位于额定磁链的 `50%~150%`。
- PLL 速度方向与目标方向一致。
- PLL 角度与 I/F 角度误差不超过 `π/3`。
- 上述条件连续保持 `0.1s`。

进入 `CLOSED` 后，控制角度在 `0.1s` 内从 I/F 角度渐变到观测角度。转速低于 `300RPM` 或磁链异常持续 `0.1s` 时回退到 I/F，避免低速观测噪声直接控制电流环。

### 16.5 速度 PI

```text
error = ol_current_rpm - observer_mechanical_rpm
P = speed_kp × error
I = I + speed_ki × error × dt
Iq_target = limit(P + I, -speed_iq_limit, +speed_iq_limit)
```

速度 PI 默认 `Kp=0.003 A/RPM`、`Ki=0.01 A/(RPM*s)`、`Iq` 上限 `2A`、执行频率 `1000Hz`。默认禁止主动制动，超速时只撤掉转矩；确认电源能吸收回馈能量后才能执行 `spbrake 1`。

### 16.7 无感调试顺序

第一步只观察观测器，不允许它接管角度和速度：

```text
olfault clear
olmode 1
slenable 1
sltakeover 0
spenable 0
olid 0
oliq 0.3
olvlimit 8
olramp 100
olspeed 800
speed
```

反复执行 `speed`，先确认：

- `Observer RPM` 的方向与 `Target RPM` 一致。
- `Flux` 接近 `0.0091Wb`，不能接近 0，也不能持续快速增大。
- `Phase err` 随转速升高逐渐减小。
- 状态能从 `OPEN_LOOP` 进入 `LOCKING`。

首次上板建议暂时把接管转速设得较高，例如：

```text
slrpm 700 500
```

确认观测稳定后，再开启速度 PI：

```text
olstop
spkp 0.001
spki 0
spiq 0.5
spbrake 0
sltakeover 1
spenable 1
olspeed 800
```

如果 `Observer RPM` 方向错误、磁链明显异常或相位误差接近 `π`，不要降低接管阈值强行闭环。应先检查相序、电流方向、电阻、电感、磁链和 `Vα/Vβ` 极性。无感接管错误会让 Park 角度突然偏转，可能立即产生大电流。

## 17. Detect 偏移检测为什么看起来不动

### 17.1 根因与修复

`DETECT_Offset()` 会直接切换 TIM1 的三相输出模式，FOC 的 DMA 中断也会通过 SVPWM 更新 TIM1。两边同时运行时，检测刚写入的配置可能立刻被 FOC 中断覆盖；加入无感观测器后，中断计算量也更大，严重时初始化任务会长时间得不到运行，看起来像程序停在 `Detect_Init()`。

现在使用 `s_detect_active` 做互斥：

1. 检测开始时先置位互斥标志、撤销电机运行命令并关闭三相 PWM。
2. DMA 硬件仍然继续更新 `ADC_Value[]`，所以偏移采样不会停止。
3. `Motor_DmaInt()` 看到检测标志后立即返回，不再执行保护、无感观测器、PI 或 SVPWM。
4. 检测结束后先确认 PWM 已关闭，再清除互斥标志。
5. 上电初始化任务会保存检测前的运行指令，等三相 PWM 模式恢复后才重新下发目标转速，避免 PI 在输出关闭期间提前积分。

### 17.2 正常等待时间

启动时的 `Detect_Init()` 调用 `DETECT_Offset(TRUE)`，正常大约需要 5 秒，并不是死循环：

- 等待电路稳定：约 1 秒。
- A、B、C 三相各采样 1000 次：每相约 1 秒。
- 三相关闭后再采样未驱动电压：约 1 秒。

串口应依次看到：

```text
Detect offset: begin
Detect offset: phase A
Detect offset: phase B
Detect offset: phase C
ADC_RAW [...]
Current Offset [...]
Volt Offset [...]
Detect offset: undriven voltage
Detect offset: done
```

Shell 中执行 `detect` 或 `detect 1` 都会运行电流/电压偏移校准（通常约 4 秒）；`detect 2` 为霍尔检测。偏移检测本来就不要求电机转动。两种调用方式的检测后行为不同：

偏移校准按 VESC 的时序执行：设为 50% 占空比后依次使能 A/B/C 相并分别平均。这一流程针对 PWM 开关时的测量状态，不能仅用 `olstop` 下的瞬时读数判定校准失败。

- 上电调用 `Detect_Init()`：保存参数初始化阶段的目标转速。当前调试默认值为 `ol_enable=false`、`ol_target_rpm=500RPM`，所以检测和 PWM 恢复后仍保持停机，但目标 `500RPM` 会保留，可直接执行 `olstart`；也可以通过 `olspeed <RPM>` 设置新目标。只有用户主动把默认 `ol_enable` 改为 `true` 时，才会自动起转并打印 `Startup run restored`。
- Shell 手动执行 `detect 1`：为避免检测后突然自动起转，继续保持停机，需要重新执行 `olspeed <RPM>` 或 `olstart`。

## 18. 提高到 2000RPM 后突然停机

### 18.1 当前默认配置仍是 I/F 开环

当前代码虽然启用了无感观测器，但默认配置是：

```text
sensorless_enable   = true
sensorless_takeover = false
speed_enable        = false
```

因此把 `ol_target_rpm` 调到 `2000RPM` 并不等于已经实现 2000RPM 无感速度闭环。`ol_current_rpm` 只是软件生成的强制角度斜坡，转子即使没有跟上，该数值仍会继续上升。

当强制旋转磁场逐渐快于真实转子时，电机会失步。失步后 D/Q 坐标方向错误，电流 PI 可能迅速打到电压限幅并产生电流尖峰，随后触发过流锁存，表现为“先转一会，然后瞬间停住”。电源能力不足时也可能由母线跌落触发欠压锁存。

另外必须确认 `ol_pole_pairs` 等于电机真实极对数。当前示例值是 `2`，而旧注释曾错误写成“4 对极”。极对数错误时，软件显示的机械 RPM 和真实同步机械转速不一致，也会使无感转速换算错误。

### 18.2 使用故障快照确认原因

停机后不要立即清除故障，先执行：

```text
olfault
olstatus
```

故障锁存后控制器会复位无感观测器，所以此时再执行 `speed` 通常只能看到清零后的状态；首发故障快照才是停机后的主要依据。`speed` 应在较低转速的分级测试过程中反复观察。

新版 `olfault` 会显示可读故障名以及首发故障瞬间的数据，例如：

```text
Fault = 4 ABS_OVER_CURRENT (LATCHED)
At fault: Ipeak=10.231A Vbus=23.70V target=2000RPM ramp=1365RPM
At fault: measured speed unavailable (I/F open-loop)
```

常见结果：

- `ABS_OVER_CURRENT`：优先检查失步、相序、电流采样方向、PI 参数、Iq 和极对数，不要直接提高 10A 阈值。
- `UNDER_VOLTAGE`：检查电源限流、线缆压降、母线电容和实际 `Vbus`，不要直接降低 8V 阈值。
- `MOTOR_STALL` / `MOTOR_SPEED_LOSS`：说明当时已经有有效无感速度反馈，应同时检查 `speed` 中的观测转速、磁链和相位误差。

### 18.3 安全复测顺序

先降低电流和目标，只观察无感估算，不授权接管：

```text
olfault clear
olmode 1
slenable 1
sltakeover 0
spenable 0
oliq 0.3
olramp 50
olspeed 500
speed
```

确认 `500RPM` 稳定后再依次测试 `800RPM`、`1000RPM`，每一级都检查 `olfault`、`Observer RPM`、`Flux` 和 `Phase err`。在观测方向、磁链和相位都稳定以前，不要直接用 I/F 强拖到 `2000RPM`，也不要开启速度 PI。

## 19. 无感启动的转子预对齐

### 19.1 为什么需要预对齐

无霍尔、无编码器的 PMSM 停机时，软件不知道转子磁钢的真实位置。若从零速立刻让 I/F 电角度旋转，定子磁场可能从转子两侧拉扯磁钢，外观表现为“来回摆动但不转”；继续提高速度后，转子会失步并触发过流。

现在 I/F 启动增加了预对齐阶段：

```text
启动命令
  → 固定 ol_align_angle，不积分 I/F 角度
  → Id = ol_align_current，Iq = 0，保持 ol_align_time
  → 转子吸到固定磁场位置
  → 清除对齐阶段 PI/观测器状态
  → 从该固定角开始 I/F 低速斜坡
```

这里使用的是 `Id`，不是 `Iq`：`Id` 产生固定励磁磁场，用来定位转子；`Iq` 产生转矩，会让未知初始位置的转子继续摆动。

### 19.2 默认参数与 Shell 命令

为防止烧录时自动高速起转，默认上电保持停止。首次建议使用：

```text
olfault clear
olalign 1 0.5 0.3
oliq 0.3
olramp 20
olspeed 100
```

`olalign <0|1> <Id_A> <time_s> [angle_rad]` 只能在电机停止时修改：

- `Id_A`：对齐电流，先用 `0.5A`；若仍无明显定位力，可逐步试 `0.6A`，不要一次大幅提高。
- `time_s`：固定磁场保持时间，默认 `0.3s`；通常 `0.2~0.5s` 足够。
- `angle_rad`：固定电角度，默认 `0`，一般不需要修改。

执行 `olstatus` 可看到 `Align cfg` 和 `Align run`。启动后的前 `0.3s` 轴会短暂吸到一个位置，这是正常的预对齐动作；随后才开始平滑转动。若只摆动、不连续转动或再次报警，立刻执行 `olstop`，不要继续升速。

## 20. 电机运行时串口命令卡顿

### 20.1 原来的发送方式为什么会卡

原来的 `printf` 和 Letter Shell 都采用轮询发送：每写一个字符，都要等待 UART 的 `TXE`（发送数据寄存器为空）标志。UART 设置为 `460800 baud` 后，一个 8N1 字符在物理线上仍约需 `21.7us`。`olstatus` 有大量文字和浮点数，命令任务会在逐字符等待中反复被 30kHz、优先级更高的 FOC DMA 中断抢占，因此终端看起来输出很慢，输入下一条命令也要等待。

提高命令任务优先级不能解决这个问题：任务优先级只影响任务之间的调度，不能阻止高优先级 FOC 中断抢占。也不能直接降低 TIM1 PWM 频率来迁就串口，否则会同时改变功率级开关频率。正确做法是保留 15kHz PWM 和 30kHz 双边采样，只使用已有的 `FOC_CONTROL_LOOP_FREQ_DIVIDER` 对控制运算分频，并同步修正 `dt`。

### 20.2 现在的异步发送结构

调试串口仍使用 UART4，接收和发送分别占用两个互不冲突的 DMA 流：

```text
接收：UART4_RX → DMA1 Stream2 / Channel4 → 128B 接收缓冲区
发送：printf / Shell → 2KB 软件环形缓冲区
                    → DMA1 Stream4 / Channel4 → UART4_TX
```

发送流程如下：

1. `printf`、`Bsp_Usart_PutBuf()` 和 Letter Shell 统一调用 `Bsp_Usart_PutChar()`。
2. DMA 初始化前的早期启动日志仍使用轮询方式，保证上电初始化顺序不被破坏。
3. DMA 初始化完成后，`Bsp_Usart_PutChar()` 只把字符放进 2KB 环形缓冲区，不等待字符从 TX 引脚发出。
4. `Bsp_Usart_TxDmaStartLocked()` 找到环形缓冲区中的一段连续数据，一次交给 DMA 发送。
5. DMA 完成中断推进 `tail`，若缓冲区还有数据，立即启动下一段；只有内存回绕时才会自然拆成两段。
6. 命令输出和 Shell 的 `Return` 共用同一 FIFO，入队先后就是显示先后，因此命令结束时不再调用阻塞式 `Bsp_Usart_Flush()`。

`Bsp_Usart_Flush()` 仍然保留，只用于“必须确认最后一个字符已经离开 TX 引脚”的特殊场景；普通状态打印不要调用它。

### 20.3 缓冲区满时的处理

- 普通任务连续输出超过 2KB 时，会短暂等待 DMA 腾出空间，不会覆盖尚未发送的数据。
- 中断或已经关闭中断的临界区不能等待 DMA 完成，否则会形成死锁；这类上下文只有在缓冲区已满时才放弃新字符。
- FOC DMA 中断中不要加入 `printf`。实时中断只做采样和控制，调试信息应保存到变量中，再由 Shell 命令读取。

### 20.4 上板验证

烧录后，电脑串口保持 `460800、8N1、无流控`。先在停机状态执行一次：

```text
olstatus
```

再让电机以已经验证可起转的电流运行，例如当前电机可先使用：

```text
olstop
olfault clear
olmode 1
olalign 1 0.5 0.3
oliq 0.8
olramp 10
olspeed 100
olstatus
olstatus
```

判断结果：

- 两次 `olstatus` 应连续、完整打印，`Return` 不应插到状态文字中间。
- 电机运行时输入 `olstop`，命令应能及时响应，不应等前一页逐字符慢慢发完才执行。
- 若完全没有输出，优先检查 `DMA1_Stream4_IRQHandler()` 是否进入，以及 UART4_TX 是否确实配置为 DMA1 Stream4 / Channel4。
- 若文字乱码但速度正常，检查电脑端波特率是否仍误设为 `115200`。

### 20.5 第二阶段优化：释放 FOC CPU 时间

发送改为 DMA 后，如果电机一转起来 `olstatus` 仍明显变慢，瓶颈已经不在串口线上，而是命令任务得不到足够 CPU 时间。I/F 运行时每次 FOC 都会执行电流采样、保护、Park/反 Park、PI、SVPWM、无感磁链观测器、快速 atan2、平方根和 PLL；原配置在 ADC 上下半周期各执行一次，共 `30000 次/秒`。

现在设置：

```c
#define FOC_CONTROL_LOOP_FREQ_DIVIDER 2
```

结果是：

- TIM1 功率 PWM 仍为 `15kHz`，没有改变 MOS 开关频率。
- ADC 仍以 `30kHz` 双边采样，采样硬件链路没有改变。
- 三相采样换算以及过流、欠压等故障保护仍在每个 ADC 回调执行，即保持 `30kHz`、约 `33us` 的检查间隔。
- 电流环、无感观测器、速度环和 SVPWM 每两个 ADC 回调执行一次，即 `15kHz`。
- FOC 的 `dt` 从 `1/30000s` 自动变成 `2/30000s`，所以转速斜坡、PI 和观测器积分仍保持真实时间，不会慢一半；保护使用独立的 `1/30000s`。

另外，`olstatus` 不再执行约 30 次边格式化边发送的 `printf`。它先通过 `vsnprintf` 在 2KB RAM 缓冲区中生成完整状态页，再一次性交给 UART DMA，减少标准输出层和串口驱动的反复调用。

新状态页会增加两行：

```text
  FOC loop   : 15000 Hz adc=30000 div=2 avg=...us max=...us load=...%
  UART TX    : DMA @ 460800 baud
  Status fmt : ... us (RAM)
```

判断方法：

- `UART TX : DMA`：说明发送 DMA 已真正初始化；若显示 `POLLING`，继续检查 DMA1 Stream4 初始化。
- `FOC loop : 15000 Hz adc=30000 div=2`：说明采样/保护保持 30kHz，而完整 FOC 分频为 15kHz。
- `Status fmt`：生成整页 RAM 文本所用的墙钟时间，已经包含中途被 FOC 中断抢占的时间；通常应远小于 `100000us`。
- `avg` 是 30kHz ADC 中断轻、重两条路径的平均耗时，`load = avg_us × 30000 / 10000`，表示整个 ADC/FOC 中断链占一个 CPU 核心时间的近似百分比。
- `load < 60%`：命令任务通常应当流畅。
- `load 60%~80%`：可以运行，但浮点状态页仍可能稍慢。
- `load > 80%`：无感或数学运算仍然过重，应继续优化观测器执行频率，不能再靠提高串口波特率掩盖。

## 21. 2000RPM 运行一段时间后停机的修复

### 21.1 已确认的根因

之前保存的首发故障为：

```text
Fault = 4 ABS_OVER_CURRENT (LATCHED)
At fault: Ipeak=10.345A Vbus=23.75V target=2000RPM ramp=1353RPM
At fault: measured speed unavailable (I/F open-loop)
```

这几项数据可以连起来理解：

1. `target=2000RPM` 是用户要求的最终目标。
2. `ramp=1353RPM` 是故障时软件正在积分的 I/F 强制转速，不是真实转速。
3. `measured speed unavailable` 说明当时无感观测角还没有接管，速度 PI 也没有真实反馈。
4. I/F 磁场继续加速而转子没有完全跟上后发生失步，D/Q 坐标方向随之错误。
5. 电流 PI 为追赶错误的电流方向快速增加输出，三相瞬时电流达到约 `10.345A`，最终由绝对过流保护锁存停机。

因此，这次停止不是“2000RPM 定时停机”，也不是电源面板显示的平均输入电流达到 10A，而是 I/F 在约 1353RPM 失步后产生了很短的相电流尖峰。

### 21.2 新的启动与高速失锁保护

本次修改把 I/F 明确限制为“只负责启动”，不能再一直强拖到 2000RPM：

```text
0RPM
  -> I/F 预对齐和加速
  -> 到 800RPM 安全上限后保持
  -> 等待 F/S/D/P 四项接管条件连续成立
  -> 用 0.20s 把控制角从 I/F 平滑过渡到观测角
  -> blend=1.00 后才解除 800RPM 上限
  -> 无感速度 PI 继续加速到最终目标
```

相关参数为：

```text
sensorless_transition_rpm   = 500RPM
sensorless_fallback_rpm     = 300RPM
sensorless_openloop_max_rpm = 800RPM
sensorless_phase_tolerance  = 1.40rad
sensorless_blend_time       = 0.20s
```

另外修复了闭环后的失锁处理：

- 当前转速仍在 I/F 安全区内时，允许从无感闭环回退到 I/F。
- 已经高于 `sensorless_openloop_max_rpm` 时，不再慢慢回退到高速 I/F；观测器连续失锁后直接锁存 `MOTOR_SPEED_LOSS`。
- `Motor_DmaInt()` 在本次 FOC 结束前再次检查故障锁存，并立即覆盖为安全占空比，不等待下一次控制周期继续输出。
- 停机后使用 `olfault` 可以看到故障瞬间的无感状态、磁链、相位、D/Q 电流、PI 电压和 F/S/D/P 条件。

### 21.3 `slguard` 命令

新命令格式：

```text
slguard <openloop_max_rpm> <phase_tolerance_rad> <blend_time_s>
```

例如：

```text
slguard 800 1.40 0.20
```

三个参数的含义：

- `800`：观测角尚未 100% 接管时，I/F 最多运行到 800 机械 RPM。
- `1.40`：接管前，观测角与 I/F 角的最大允许误差约为 80°；程序最多允许 `1.50rad`，不能为了强行接管而放宽到 90°以上。
- `0.20`：角度在 0.20 秒内平滑切换，避免一拍切角产生电流冲击。

该命令会复位无感观测器，只允许在 `olstop` 后执行。把 `openloop_max_rpm` 设为 `0` 会关闭高速 I/F 保护，调试阶段不要这样设置。

### 21.4 第一次上板验证命令

先不要直接要求 2000RPM。使用已经确认可以起转的 `0.8A`，先验证 800RPM 无感接管：

```text
olstop
olfault clear
olmode 1
olalign 1 0.5 0.3
oliq 0.8
olramp 50
slenable 1
slrpm 500 300
slguard 800 1.40 0.20
sltakeover 1
spkp 0.001
spki 0.005
spiq 1.2
spbrake 0
spenable 1
olspeed 800
```

`olramp 50` 从 0 加速到 800RPM 大约需要 16 秒。等待稳定后执行：

```text
olstatus
```

只有以下关键项同时满足，才继续升速：

```text
Sensorless : CLOSED (ENABLED)
SL takeover: ARMED
SL checks  : F=1 S=1 D=1 P=1 ... blend=1.00 ...
Observer RPM: 接近 800
Meas RPM   : 接近 800
Fault      : 0 NONE (CLEAR)
```

F/S/D/P 分别表示：

- `F`（Flux）：估算磁链是否处于电机额定磁链的合理范围。
- `S`（Speed）：观测转速是否达到门槛，并且与当前 I/F 斜坡转速大致一致。
- `D`（Direction）：观测方向是否与目标方向一致。
- `P`（Phase）：观测角与 I/F 强制角是否在允许误差内。

如果 `Target RPM` 已设为 2000，但 `Current RPM` 保持在 800，表示保护正在正常工作：无感接管还没有完成。此时不要提高 Iq、过流阈值或关闭 `slguard`，应根据为 0 的 F/S/D/P 项继续排查，并把完整 `olstatus` 保存下来。

### 21.5 分级升到 2000RPM

800RPM 已确认 `CLOSED`、`blend=1.00` 后，再逐级下发：

```text
olspeed 1200
olstatus
olspeed 1600
olstatus
olspeed 2000
olstatus
```

每次应等待 `Current RPM` 和 `Meas RPM` 接近本级目标后再执行下一条。若中途停机，不要先执行 `olfault clear`，先保存：

```text
olfault
olstatus
```

结果判断：

- `MOTOR_SPEED_LOSS`：已经进入无感闭环，但高速时磁链、方向或反馈转速连续失效；检查 `SL checks`、电机 R/L/磁链、极对数和相序。
- `ABS_OVER_CURRENT`：查看快照中的 `SL`、`Iq/IqCmd`、`VdInt/VqInt` 和 `phase`；不要直接提高 10A 阈值。
- `UNDER_VOLTAGE`：检查故障快照中的 `Vbus`、电源限流、线缆压降和母线电容。
- 始终停在 800RPM 且无故障：接管条件没有全部成立，完整 `olstatus` 会指出是 F、S、D、P 中哪一项阻塞。

## 22. VESC 风格电机参数检测

### 22.1 能检测什么

新增的 `detect motor` 按顺序检测：

1. 三相电流和相电压偏置。
2. 电机相电阻 `R`，单位 Ω。
3. D/Q 平均相电感 `L`，单位 H，Shell 中以 `uH` 显示。
4. 永磁体磁链 `flux linkage`，单位 Wb，Shell 中以 `mWb` 显示。

极对数必须单独说明：在没有霍尔、编码器、机械测速仪或人工机械圈数的情况下，控制器只能看到电角度，无法知道转子机械角度。不同极对数的电机都可能产生完全相同的电气波形，因此不能仅凭三相电压、电流唯一推导极对数。VESC 的纯无感检测同样不会凭空得到极对数，`si_motor_poles` 通常由用户输入，或由编码器电角度/机械角度比值计算。

本工程提供：

```text
detect poles <electrical_rpm> <measured_mechanical_rpm>
```

例如检测磁链时使用 `1200 electrical RPM`，外部测速仪读到 `600 mechanical RPM`：

```text
detect poles 1200 600
```

结果为 `2` 极对。如果电机转子上能够直接数出永磁体磁极数，也可以使用：

```text
极对数 = 磁极总数 / 2
```

### 22.2 为什么检测必须在15kHz中断中执行

不能在 Shell 任务中每隔 `1ms` 直接修改一次 PWM 来测 R/L：任务调度会被串口、系统任务和中断打断，实际脉冲宽度不稳定，计算出的 `di/dt` 会产生很大误差。

现在检测分为两层：

```text
Shell命令
  -> 创建独立的 Motor Detect 后台任务并立即返回
  -> 因此 Shell 仍能响应 olstop / detect abort

Motor Detect后台任务
  -> 检查停机和故障
  -> 依次启动偏置、R、L、磁链阶段
  -> 每1ms等待阶段完成，不直接控制PWM

ADC-DMA中断（30kHz采样、15kHz检测控制）
  -> 电流/电压采样
  -> 绝对过流保护
  -> 固定角度电流PI或双极性电压脉冲
  -> 累加R/L/磁链样本
  -> 完成、失败或超时后立即输出安全占空比
```

偏置检测仍由任务独占 TIM1，因为它需要依次改变 A/B/C 三个桥臂的输出模式；此时 `Motor_Detect_ControlIsActive=false`，DMA 只更新 ADC 原始数组，不参与 PWM 控制。

### 22.3 相电阻检测

电阻检测使用固定电角度和 D 轴电流：

```text
Id：0 -> 检测电流，0.8s平滑上升
Iq：0
固定电角度：0rad
稳定等待：0.2s
采样时间：0.5s
```

转子会先被吸到固定磁场方向，稳定后反电动势近似为零。检测周期累计电压、电流矢量模长：

```text
R = average(sqrt(Vd² + Vq²)) / average(sqrt(Id² + Iq²))
```

结果必须在 `0.005~10Ω` 范围内，否则返回 `RESISTANCE_INVALID`。低电流测量容易被 MOS 管压降、死区和采样偏置影响，因此默认使用已经验证可以驱动本电机的 `0.8A`，也允许命令指定 `0.3~2.0A`。

### 22.4 相电感检测

电感检测先固定转子，然后在同一电轴施加 `+0.5V/-0.5V` 双极性短脉冲：

```text
每个半脉冲：8个15kHz控制周期
有效斜率时间：(8 - 1) / 15000 秒
正负脉冲交替：避免电流和转矩向单方向累积
有效样本：至少60个，目标120个
```

每个半脉冲使用电机电压方程：

```text
V = R × I + L × dI/dt
L = (V - R × I平均值) / (dI/dt)
```

最后与 VESC 的处理思路一致，将平均值乘以 `0.9`。观测器通常可以容忍 L 略微低估，而高估 L 更容易导致磁链观测器不稳定。结果必须在 `5uH~50mH` 范围内。

这里检测的是当前硬件和当前转子位置下的平均电感，不包含完整的 HFI 多角度扫描，因此不会分别给出高精度 `Ld`、`Lq` 和磁阻差；对于凸极明显的 IPMSM，需要后续增加六矢量/多角度 HFI 扫描。

### 22.5 磁链检测

磁链检测使用刚刚测得的 R/L，并临时按 VESC 的 `1.5ms` 电流环时间常数设置检测 PI：

```text
Kp = L / 0.0015
Ki = R / 0.0015
```

这些 PI 参数只在磁链检测期间使用，结束后自动恢复用户原来的 `olkp/olki/olvlimit`。

检测过程：

```text
固定Id预对齐：1s
Id平滑切换到Iq：0.5s
电气转速斜坡：4s
目标转速稳定：1s
磁链采样：1s
默认目标：1200 electrical RPM
```

磁链公式与 VESC 开环磁链检测相同：

```text
ωe = electrical_rpm × 2π / 60
|V| = sqrt(Vd² + Vq²)
|I| = sqrt(Id² + Iq²)
flux = (|V| - R × |I|) / ωe - L × |I|
```

磁链阶段会真实转动电机，因此必须卸载轮子、皮带和机械负载。若电机没有跟上开环电气转速，计算值不可信；检测时应观察电机是否连续旋转，而不是只看 Shell 返回成功。

### 22.6 Shell命令

兼容原命令：

```text
detect
detect 1
detect offset
```

以上三种写法都执行电流/电压偏置检测。霍尔检测仍可使用：

```text
detect 2
detect hall
```

自动检测 R/L/磁链：

```text
detect motor [current_A] [electrical_rpm]
```

默认值：

```text
detect motor 0.8 1200
```

该命令创建后台任务后立即返回。检测通常需要十几秒，期间仍可输入：

```text
olstop
```

或：

```text
detect abort
```

两者都会立即撤销检测状态、输出安全占空比并关闭三相桥臂。后台任务随后打印 `USER_ABORT`，不会继续进入下一检测阶段。

查看最近一次结果：

```text
detect show
```

结果确认合理后，应用并保存到 EasyFlash：

```text
detect apply
```

`detect apply` 会更新：

- `foc_motor_r`
- `foc_motor_l`
- `foc_motor_flux_linkage`
- `sensorless_motor_r`
- `sensorless_motor_l`
- `sensorless_flux_linkage`
- 已有机械参考时的 `ol_pole_pairs`

上电时 `Motor_Detect_LoadStoredParameters()` 在代码示例默认值之后加载检测结果，因此已保存的检测值不会再被 `motor_param.c` 中的示例值覆盖。

### 22.7 推荐首次操作顺序

```text
olstop
olfault clear
detect motor 0.8 1200
等待后台打印 Detect motor finished
detect show
```

先检查：

- `Status = NONE`
- R/L/Flux 都为 `VALID`
- R、L、磁链与电机尺寸和旧参数数量级接近
- 磁链阶段电机实际连续旋转

有机械测速仪时，在磁链阶段记录机械 RPM，然后执行：

```text
detect poles 1200 <机械RPM>
detect show
detect apply
```

没有机械测速仪、霍尔或编码器时，不要根据观测器显示的机械 RPM 反算极对数，因为该 RPM 本身已经除以当前配置的极对数，会形成循环证明。此时应查电机资料或数转子磁极。

### 22.8 错误结果

- `BUSY`：已有偏置或参数检测正在占用 PWM。
- `MOTOR_RUNNING`：先执行 `olstop`。
- `FAULT`：先执行 `olfault` 查看首发故障，排除后再清除。
- `TIMEOUT`：DMA检测状态机没有在规定时间内完成。
- `CURRENT_TOO_HIGH`：检测相电流超过4A软件检测上限，立即停止输出。
- `RESISTANCE_INVALID`：稳态电流不足、采样偏置错误或结果超范围。
- `INDUCTANCE_INVALID`：脉冲电流变化太小、过大或有效样本不足。
- `FLUX_INVALID`：电机未跟上电气转速、输出饱和或R/L结果错误。
- `MECHANICAL_REFERENCE_INVALID`：电气RPM/机械RPM比值不接近1~50之间的整数。
- `USER_ABORT`：用户通过 `olstop` 或 `detect abort` 主动中止。

任何阶段出现异响、只抖动不连续旋转或电源明显限流，都应立即执行 `olstop`，不要直接增大检测电流、电压脉冲或软件过流阈值。

### 22.9 本机参数检测标定记录

本机使用普通万用表测得线间电阻约 `1.1Ω`，表笔短接约 `0.5Ω`，因此线间电阻约为 `0.6Ω`。对称星形电机用于 FOC 的相电阻约为线间值的一半，即约 `0.3Ω`。

电阻检测不能直接把每个采样点的 `V/I` 当成绕组电阻。逆变器存在近似固定的管压降和死区压降，因此采用三个稳态点拟合：

```text
V = R * I + Voffset
```

拟合斜率 `R` 才是相电阻，截距 `Voffset` 是逆变器等效固定压降。当前实测：

```text
I/V points: 0.8338A/0.3665V, 1.2233A/0.4424V, 1.6186A/0.5324V
R = 0.211403Ω
Voffset = 0.1881V
R² = 0.9980
```

每点显示的 `V/I` 为包含固定压降的表观电阻，因此会从 `0.4396Ω` 随电流增加下降到 `0.3289Ω`；它与最终拟合斜率不同是正常现象。

本机电桥测得线间电感约 `800µH`。对称星形电机的 FOC dq 相电感通常按下面关系换算：

```text
Ldq ≈ Lline-line / 2 ≈ 400µH
```

双极性脉冲检测的内部累计量是检测链路半量，转换为 FOC dq 相电感时乘 `MOTOR_DETECT_INDUCTANCE_DQ_FACTOR = 2.0`；随后乘 `MOTOR_DETECT_INDUCTANCE_STABILITY_SCALE = 0.9` 略微低估，以提高观测器稳定性。修正前自动检测为 `194.47µH`，按新口径预计约为：

```text
194.47µH * 2 ≈ 388.94µH
```

该结果应与线间电桥值换算出的约 `400µH` 比较，不能把自动检测的 dq 相电感直接与 `800µH` 线间值比较。

检测和应用步骤：

```text
olstop
olfault clear
detect motor 0.8 1200
detect show
```

只有满足以下条件才执行 `detect apply`：

- 电阻拟合 `R² >= 0.95`；
- 相电阻与线间电阻的一半数量级一致；
- dq 相电感与线间电感的一半数量级一致；
- 磁链阶段电机确实连续旋转；
- 检测过程没有 `CURRENT_TOO_HIGH` 或其他故障。

### 22.10 磁链与反电势常数校验

磁链阶段必须使用三相端电压采样值，不能直接把电流 PI 的指令电压当成电机实际端电压。程序将 `va/vb/vc` 做 Clarke/Park 变换得到实测 `Vd/Vq`，并使用本轮刚测得的 `R/L` 按稳态 q 轴方程计算：

```text
flux = abs((Vq_measured - R * Iq) / omega_e - L * Id)
```

对正弦电机，FOC 相磁链与机械转速下的线间 RMS 反电势常数关系为：

```text
Ke[V/krpm] = 128.25498 * pole_pairs * flux[Wb]
```

ATK-BL57H95D20E 参数表给出 4 个磁极，因此极对数为 2；线间 RMS 反电势常数为 `6.6V/krpm`，对应参考磁链：

```text
flux_ref = 6.6 / (128.25498 * 2) = 0.02573Wb = 25.73mWb
```

检测结束会同时打印平均实测 `|Vq|` 和换算后的 `Ke`。只有电机确实跟随 `1200 electrical RPM`（2 极对时约为 `600 mechanical RPM`），并且换算 `Ke` 与铭牌数量级一致时，磁链结果才可应用。

HD75 板通过 PC13 控制三相端电压 RC 滤波器。PC13 必须初始化为输出，运行检测时拉高使能滤波器。如果保持 MCU 复位后的输入模式，即使调用 `PHASE_FILTER_ON()` 也只会修改无效的 ODR 锁存位，ADC 将采到 PWM 开关节点瞬时值。典型故障表现是电机已经旋转，但平均实测 `|Vq|` 只有约 `0.1V`，换算 `Ke` 远低于铭牌。

本机实测至少约 `1.5A` 才能可靠起转，因此磁链阶段不能沿用命令默认的 `0.8A`。程序只对磁链阶段设置 `1.5A` 最小电流；电阻仍使用 `0.8/1.2/1.6A` 三点拟合。磁链时序为 `1s` 对齐、`1s` Id/Iq 过渡、`8s` 转速斜坡，随后立即关闭功率管并进行 `0.5s` 滑行反电势采样，阶段超时为 `18s`。

磁链阶段还采用 VESC 风格的占空比有效性检查。程序记录锁定转子维持电流时的 `duty_still`、升速过程中的 `duty_max` 和当前 `duty_now`。到达目标电气转速后必须满足：

```text
duty_now >= max(0.03, duty_still * 1.5)
duty_now >= duty_max * 0.70
```

第一项用于识别堵转：如果旋转后的电压需求仍与静止绕组压降接近，转子没有产生可信反电势。第二项用于识别失步：占空比从升速峰值下降超过 30% 时，不再继续计算磁链。失败时 Shell 会打印 `duty still/now/max` 并返回 `FLUX_INVALID`。

最终磁链不再使用带电运行期间的指令转速或 PI 电压。通过占空比检查后，程序关闭六个 MOSFET，但保留 TIM1、ADC/DMA 和相电压 RC 滤波器，在 `0.5s` 自由滑行窗口中测量反电势。每个采样周期由 `atan2(Vbeta, Valpha)` 的相位增量计算真实电角速度，再计算：

```text
omega_e = abs(delta(atan2(Vbeta, Valpha)) / dt)
flux = sqrt(Valpha^2 + Vbeta^2) / omega_e
```

只有滑行电气转速高于 `100 eRPM` 且有效样本足够时才返回成功。该方法不依赖转子是否精确跟随加速阶段的指令转速，也不需要在磁链公式中扣除 `R*I` 或 `L*dI/dt`，因为采样时逆变器已经处于高阻、电流接近零。

磁链加速阶段采用工程已经验证过的 V/F 参数，而不是 q 轴电流闭环：

```text
Vq = (1.0V + 0.057V/Hz * electrical_hz) * transition
```

V/F 对临时角度误差和参数偏差更宽容，适合空载加速后立即滑行测量；全过程仍保留相电流软/硬保护。滑行采样还要求反电势矢量幅值大于 `0.20V`，避免把 ADC 噪声误判成数百 eRPM。

HD75 原理图中三相电压 SENS1/2/3 的分压电阻是 `39kΩ/2.2kΩ`，而母线电压分压是 `56kΩ/2.2kΩ`。相电压换算必须使用独立的 `PHASE_VOLTAGE_R1/R2`，不能复用 `VIN_R1/R2`。
