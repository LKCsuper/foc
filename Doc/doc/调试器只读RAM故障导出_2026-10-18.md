# 调试器只读RAM故障导出

## 本次改动与边界

- 复用已有512条、每条84字节的故障环形记录，不新增大缓冲，不改15 kHz控制频率、外设、增益和原过流保护。
- 现有记录仍每4个控制拍采一条，故障入口强制采样并冻结；正常停机也冻结。新增描述符仅在武装、冻结或缓冲复用时发布，不逐拍维护描述符，不增加RTT输出或中断内格式化。
- 记录是在同一入口集中复制，但不同字段有明确流水关系：ADC、abc、母线、dt属于本拍采样；CSV的prev_*属于此前完整控制结果，不是上一条266 us记录；time_us不是ADC采样孔径时间戳。flux字段是模长，不是磁链αβ向量。不要把字段统一解释成同一物理时刻。
- 新功能需烧录对应固件，旧固件不具备描述符。本版已烧录校验，并完成停机读出验证与300 RPM真实运行记录导出；未做高速或故障诱发测试，详见下方实机记录。

## 使用流程

1. 烧录匹配当前map的固件，确认停机且无锁存故障后，使用原命令`sltrace fault`武装。不会自动启用电流跟踪观察，也不自动清除电机故障。
2. 只有得到安全条件确认才执行既定低速测试，不因导出功能直接升速。故障会自动冻结；正常测试结束仍需先停机、目标归零并确认状态。
3. 停机执行`sltrace debug`，冻结并只返回描述符地址、长度和条数，不逐行打印轨迹。运行中拒绝此命令；已有故障不妨碍保留和读取数据。
4. 在仓库根目录执行导出，不需要串口参与数据传输：

```powershell
python Scripts/jlink_fault_trace.py --jlink "D:\Users\15403\AppData\Local\Keil_v5\ARM\Segger\JLink.exe"
```

默认解析`../build/foc.map`定位`g_motor_fault_debug`，也可显式指定`--map`和`--output`。不要使用其他固件的map。ABI检查不等于对目标固件全文作了校验。

## 自动测试脚本

`sensorless_observe_test.py --fault-trace`现在默认J-Link导出，需额外提供`--jlink`或把Commander加入PATH；缺失时在串口连接、启动电机之前拒绝。

测试的原有低频状态查询及停机确认保留，本次只替换故障轨迹数据出口，不宣称整个测试全程无串口。

原串口CRC逐行导出可显式选择`--fault-export uart`，不再是自动故障导出的默认选项。若导出失败会报告错误，不会宣称采集通过，也不会为重试导出清故障或重新启动电机。

## 数据一致性与只读约束

- 描述符固定56字节、14个小端uint32字段，包含magic、版本、奇偶序号、状态、数组地址、样本大小、容量、分频、head/count、故障码与首末时间。
- 奇数序号表示发布进行中；只有偶数、frozen状态且count非零才允许读取数组。armed时head/count不是实时计数，不应用它查看记录进度。
- 导出顺序为：描述符→完整数组→描述符→第二次完整数组→描述符。三份描述符须完全相同，两份数组须逐字节相同；再校验环形几何、ADC范围、浮点有限性、保留字段、时间顺序/回绕、首末时间与末条故障码。
- 重新武装或改用其他轨迹格式会先失效旧描述符。检测到变化、截断、空记录、未知ABI或不合法地址就拒绝输出有效CSV，不拼接不同窗口。
- 脚本固定为STM32F405RG/SWD，100 kHz，只允许普通SRAM 0x20000000..0x20020000内的对齐读取；Commander文件只有connect、savebin、q，无halt/reset/写目标内存/断点/启动命令。使用支持后台访问的连接设置，不选择停机读取模式；不宣称调试总线完全零干扰。

## 输出

成功后产生`.descriptor.bin`、`.ring.bin`、`.csv`、`.json`和`.log`。CSV列与既有故障离线分析兼容；其中CRC由主机从已验证二进制生成，**不是目标端生成的传输CRC**。JSON保留数组SHA256、map SHA256、ABI、读取次数和字段时序说明。

默认文件名按北京时间生成，已有同名前缀拒绝覆盖。失败时日志可能保留，但不输出通过验证的CSV。
